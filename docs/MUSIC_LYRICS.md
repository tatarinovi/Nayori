# Музыка и тексты песен

В раскрытой карточке музыки источник справа сверху открывает список доступных MPRIS-плееров с текущим треком. Можно выбрать и приостановленный плеер: выбор сохраняется, пока он доступен. Если выбранный плеер исчезает, Nayori выбирает воспроизводящий плеер, затем первый доступный. Кнопки управления, метаданные и текст относятся к одному выбранному плееру.

Когда текст найден, он заменяет обложку, название и исполнителя. Синхронизированная строка определяется по позиции плеера; перемотка и пауза учитываются. Во время пауз между строками отображается музыкальная нота. Следующая непустая строка видна полупрозрачно; предыдущая скрыта, чтобы оставить больше места текущей. Над кнопками показана тонкая полоса прогресса трека. Текущая и следующая строки используют одну гарнитуру. Смена строки и подсветка слов используют общую длительность 220 мс; отдельные слова не сдвигаются по вертикали. Слова текущей строки плавно проявляются по позиции плеера; без пословных таймкодов время до следующей строки распределяется по числу слогов, поэтому такое выделение приблизительное. Обычный текст без таймкодов можно прокручивать внутри карточки. Кнопки управления остаются внизу, выбор плеера — сверху. После загрузки текста справа снизу появляется кнопка с иконкой текста: она переключает текст и обычные метаданные с плавным сдвигом и сменой прозрачности. При отключённых анимациях переход мгновенный. Выбор сохраняется в общей службе до перезапуска оболочки; по умолчанию автопоказ текста включён. При загрузке, отсутствии текста и инструментальном треке остаётся обычный вид карточки. В свёрнутом острове найденный текст плавно заменяет всё обычное содержимое полоски. Текущая синхронизированная строка или первая непустая строка обычного текста выводится в одну строку на всю ширину, с прокруткой при переполнении. При раскрытии в верхнюю полоску возвращаются часы, лиса и календарь/погода. Спетая часть строки плавно становится ярче поверх полупрозрачного текста; рамка мягко пульсирует акцентным цветом по ударам общего аудиовыхода при активном MPRIS-воспроизведении. При отключённых анимациях пульсация выключена. Поиск и обновление позиции работают при воспроизведении также без раскрытия Island. Уведомления и вспышка громкости сохраняют приоритет.

## Источники и кэш

Порядок поиска: LRCLIB → AMLL TTML DB → NetEase → Kugou → QQ Music → lrc.cx → lyrics.ovh. Если первый источник отдаёт только обычный текст, поиск синхронизированной версии продолжается; обычный текст остаётся запасным вариантом. Неудачный ответ одного источника не блокирует следующие.

`MusicService.qml` выбирает плеер и запускает один Python-процесс при видимой главной странице раскрытого острова или при воспроизведении в видимом свёрнутом острове. Все экраны используют общий результат. Метаданные передаются через stdin, не через аргументы командной строки. После смены трека старый процесс отменяется, запоздавшие результаты игнорируются. Строки обновляются по позиции MPRIS, распознавания речи нет.

Worker `scripts/lyrics-fetch.py` использует только стандартную библиотеку Python. Он читает JSON `{title, artist, album, duration, trackUrl, trackId}` из stdin и возвращает JSON `{status, source, lines: [{t, text}], plainText, diagnostics, cached}`. Время — в секундах. LRC поддерживает несколько отметок строки, offset и очистку пословных меток; TTML разбирается как XML с исключением перевода и фоновых вокальных партий. Название, исполнитель и длительность проверяются перед принятием результата. Однострочные заглушки и одни лишь кредиты не считаются синхронизированным текстом песни.

Автоматический кэш: `$XDG_CACHE_HOME/nayori/lyrics`, по умолчанию `~/.cache/nayori/lyrics`. Успешные результаты действуют 30 дней, индекс AMLL — неделю. Запись атомарная. Ручные LRC-файлы не требуются и не ищутся. Отрицательные ответы запоминаются только в памяти: ошибки — на 15 секунд, отсутствие текста — на пять минут. В диагностике нет самих текстов, токенов и URL запросов.

Обычный запрос ограничен четырьмя секундами, первая загрузка индекса AMLL — десятью; весь поиск — примерно 65 секундами, со страховочным таймером 68 секунд в QML. При HTTP 5xx LRCLIB выполняются до десяти попыток с задержками 0,25, 0,5, 1 с, затем по 2 с в пределах общего лимита поиска. Остальные ошибки не повторяются. Закрытие главной страницы отменяет незавершённый поиск.

При проверке 25 октября 2026 года LRCLIB, AMLL, NetEase, QQ Music, lrc.cx и lyrics.ovh отвечали. Канонический репозиторий AMLL — `amll-dev/amll-ttml-db`. HTTPS-поиск Kugou возвращал ошибку сертификата. Этот адаптер при таком ответе пропускается; проверка TLS не отключается и автоматического перехода на HTTP нет.

## Проверки

```sh
bash scripts/check-music.sh
```

Офлайн-тесты проверяют адаптеры и порядок источников, LRC/TTML, неверные совпадения, повреждённый и устаревший кэш, отбраковку заглушек. Сценарии QML проверяют запуск worker через stdin, синхронизацию, паузу, перемотку, смену и исчезновение плеера, отмену старого запроса, выбор через меню кликом, замену метаданных текстом, положение управления и прокрутку обычного текста без переключения страницы.

Реальная сетевая проверка worker получила 46 строк с таймкодами от NetEase после перехода по цепочке. Снимок искусственного сценария — `/tmp/nayori-music-widget.png`.

Фон обложки увеличен перед размытием, затем размытие и затемнение обрезаются общей скруглённой маской. Это убирает прозрачные выборки blur по границам и отдельные светлые контуры слоёв. GPU-эффект не воспроизводится software-рендером изолированного стенда; нативный вид углов требует визуальной проверки в рабочем Wayland-сеансе.
