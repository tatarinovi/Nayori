# Система в Dynamic Island

«Система» — четвёртая вкладка существующего острова. Внутреннего заголовка и подзаголовка нет; аптайм находится в бейдже карточки состояния. Три ряда содержат CPU/GPU/RAM,
диски/сеть и «Состояние»/«Питание». В нижнем ряду «Состояние» расположено слева, «Питание» — справа. Высота нижнего ряда ограничена 100 px (104 px в компактном виде); при ошибке профиля добавляется место для сообщения. Остальная высота отдана двум рядам мониторинга. Отдельная карточка температур удалена; температуры CPU и GPU остаются в соответствующих карточках. Страница не прокручивается. Недоступные показатели, датчики и целые карточки скрываются; оставшиеся карточки занимают освободившееся место. При недостатке
места включается компактное представление: сокращаются подписи, второстепенные
строки скрываются, название модели и сетевого подключения доступно в подсказках.
Существующие переходы, Escape, маршрутизация по мониторам и отключение анимаций
сохраняются. Максимальный размер раздела — 760×630; размер ограничен экраном.
Материалы и акцент берутся из `Tokens`; размытие остаётся у существующего окна
острова. Иконки раздела — единый набор `SystemIcon` с SVG-геометрией на сетке 24×24 и толщиной линий 1,75. Внешний шрифт не нужен. Заголовки всех карточек закреплены у верхнего отступа в строке высотой 26 px; текст оптически сдвинут на 1 px вниз относительно центра иконки. Свободное место занимают графики и нижние распорки. Кнопки питания имеют одинаковые ширину и высоту; группа значка и текста центрируется целиком.

## Сбор данных

`ShellRoot` создаёт один `SystemMonitor`. `SystemPage` подписывается, только когда
остров видим, раскрыт и выбрана вкладка «Система». Все экраны и виджеты рабочего
стола используют один снимок. `SystemReader` сохраняет интерфейс для виджетов;
при переданном общем сервисе его старые FileView, таймеры GPU и extra-process не
обновляют показатели. Без сервиса остаётся прежний режим для автономных стендов.

`CpuSampler` — перенесённый сборщик `surfaces/island/Cpu.qml`, который теперь
служит совместимой обёрткой. Он асинхронно читает `/proc/stat`; учитываются первые
восемь счётчиков, без двойного учёта guest. Нагрузка недоступна до двух корректных
отсчётов. Лиса и монитор используют один экземпляр; для лисы полный worker не нужен.

Один Python-worker отдаёт JSON Lines примерно раз в секунду. Чтение файлов и
внешние команды выполняются вне потока QML. При последней отписке процесс
останавливается, история и снимок очищаются. После сбоя — повтор через 2,5 секунды;
отсутствие новых данных в течение 5–8 секунд вызывает перезапуск. История хранит
не более 61 точки и не более 60 секунд для каждого существующего устройства.
Пропуски не соединяются линией, процентные графики имеют шкалу 0–100, скорости —
от нуля до максимума окна. Анимации на каждом измерении нет.

| Данные | Источник |
|---|---|
| CPU: модель, ядра, потоки, частота | `/proc/cpuinfo`, `cpufreq/scaling_cur_freq` |
| RAM | `/proc/meminfo`, `MemTotal − MemAvailable` |
| GPU | DRM/sysfs; NVIDIA — один ограниченный по времени `nvidia-smi` для всех карт |
| Модель GPU | `product_name`, необязательный `lspci -Dmm`, иначе PCI vendor/device ID |
| Файловые системы | `/proc/self/mountinfo` и `statvfs` |
| Дисковый I/O | `/proc/diskstats`, major:minor конкретного раздела или dm-устройства |
| Сетевые скорости | `/proc/net/dev`, отдельно по интерфейсам |
| Подключения Wi-Fi/Ethernet | существующий `services/status/Network.qml`, Quickshell.Networking |
| Туннели | `tun_flags`, uevent, необязательный `ip -j -d link show` |
| Температуры | `/sys/class/hwmon`, GPU hwmon или NVIDIA API |
| Время работы | `/proc/uptime` |
| Дистрибутив и ядро | существующий `SystemInfo` |
| Профиль и состояние | `powerprofilesctl get`, `systemctl is-system-running` |

Медленные сведения, PCI-имена и типы туннелей обновляются раз в 15 секунд.
`ps` вызывается раз в две секунды только при подписке подробного виджета рабочего
стола; вкладка острова такой подписки не создаёт. Все внешние команды имеют
таймаут 0,6 секунды. Обычному мониторингу не нужен root.

## Выпадающие списки

Селекторы интерфейсов и GPU передают `popupOpen` через `SystemPage` →
`IslandDashboard` → `MorphingIsland`. Существующий `ScreenPanels` учитывает его
в `dashboardPointerInside`, поэтому переход курсора в popup не запускает
автосворачивание острова. Общий `closePopups()` закрывает все списки; смена
вкладки и скрытие страницы также закрывают их. Escape сначала закрывает popup.

## Профили питания

Кнопки «Экономия», «Баланс» и «Максимум» меняют только профиль электропитания по
нажатию пользователя. Используется тот же `Quickshell.Services.UPower.PowerProfiles`,
что и на странице настроек «Питание»; выбранный профиль отражает его состояние.
Кнопки отключены, если наличие power-profiles-daemon не подтверждено чтением
`powerprofilesctl get`. «Максимум» также требует `hasPerformanceProfile`.
Ошибка синхронного вызова выводится под кнопками. Асинхронные ошибки D-Bus
обрабатывает Quickshell, активный режим остаётся связан с его моделью.

## Ограничения и отсутствие данных

- Неизвестные значения остаются `null` в снимке и скрываются в интерфейсе. Карточка GPU без доступных метрик не показывается; отсутствие температурного датчика скрывает только соответствующий бейдж CPU или GPU. Ошибка отдельного источника не отключает остальные.
- Доступные GPU выбираются в заголовке карточки. У дисков селектора нет: одновременно показаны только `/` и точки монтирования, начинающиеся с `/mnt/`, корень — первым. `/mnt` без завершающего слеша, `/home`, `/boot` и похожие префиксы вроде `/mnt-other` не включаются. Каждая строка показывает свой объём и заполнение; скорость и график добавляются при достаточной высоте, подробности доступны в подсказке. Удалённое
  устройство автоматически заменяется первым доступным; его история удаляется.
- AMD/Intel определяются через DRM. Загрузка и VRAM доступны только при наличии
  соответствующих sysfs-файлов; большинство Intel iGPU не публикует эти метрики.
  Привилегированный `intel_gpu_top` не запускается, значения не подменяются.
- Для btrfs, ZFS и bcachefs I/O скрыт: один mountinfo major:minor
  не описывает достоверно все физические устройства такой файловой системы.
- `used` вычисляется из `f_bfree`, доступное пользователю пространство — из
  `f_bavail`; резерв файловой системы не считается доступным.
- Обнаруженный туннель не доказывает, что VPN переносит весь трафик. Если туннеля
  не видно, индикатор VPN скрыт. Отсутствие NM-профиля не означает,
  что VPN выключен. Неподдерживаемые сторонние реализации могут остаться неизвестными.
- На очень маленьких поверхностях подробные подписи сокращаются. Физический
  ввод, несколько реальных GPU/мониторов и размытие композитора проверяются отдельно.

## Проверки

```bash
bash scripts/check-system-monitor.sh
python3 tests/system-monitor.py
node tests/widget-layout.cjs
bash scripts/ci-lint.sh
bash scripts/ci-tests.sh unit
dbus-run-session -- bash scripts/ci-tests.sh smoke
```

Новый offscreen-стенд: `tests/smoke/SystemMonitorSmoke.qml`. Он использует mock
метрик и профилей, проверяет ограничение истории, удаление устройств, общий
адаптер виджетов, остановку и перезапуск worker, узкую раскладку без прокрутки.

При исследовании Ryoku использовались его документация архитектуры и Controls
([ryoku.md](https://github.com/Ryoku-dev/ryoku/blob/main/docs/ryoku.md),
[plugins.md](https://github.com/Ryoku-dev/ryoku/blob/main/docs/plugins.md)).
Репозиторий распространяется под GPL-3.0. Исходные файлы мониторинга и Controls
через доступный веб-интерфейс получить не удалось; код и ресурсы из Ryoku для
этого раздела не переносились, дополнительные авторские уведомления не требуются.

## Состав изменения

- `services/system/SystemMonitor.qml`, `CpuSampler.qml`, `system_monitor.py` —
  общий сервис, CPU-сборщик и worker.
- `surfaces/island/SystemPage.qml`, `SystemGraph.qml`, `SystemIcon.qml` — карточки, графики и единые SVG-иконки.
- `IslandDashboard.qml`, `MorphingIsland.qml`, `DynamicIsland.qml`, `Fox.qml`,
  `Cpu.qml`, `surfaces/panel/ScreenPanels.qml`, `shell.qml` — навигация, размеры,
  подписки и общий CPU.
- `services/status/Network.qml`, `surfaces/desktop/SystemReader.qml`,
  `DesktopWidgets.qml` — имена подключений и переиспользование общих данных.
- `tests/system-monitor.py`, `tests/smoke/SystemMonitorSmoke.qml`,
  `tests/smoke/ShelfSmoke.qml`, `scripts/check-system-monitor.sh`,
  `scripts/ci-tests.sh` — регрессии и подключение проверок.
- `docs/ARCHITECTURE.md`, `ISLAND_INTERACTION.md`, `SYSTEM_MONITOR.md`,
  `tests/smoke/README.md` — описание поведения и стендов.

Проверка настоящего worker в этой среде дала четыре снимка без ошибок источников:
модель CPU, RAM, 12 точек монтирования и 24 температурных датчика прочитаны.
Обнаруженный DRM GPU не публикует загрузку, температуру и VRAM через доступные
источники, поэтому его карточка скрыта. В `/proc/net/dev` этой среды нет внешних
сетевых интерфейсов; сетевые скорости и подключения проверены на фикстурах.
Полноценная Wayland-сессия, смена реального профиля питания и измерение RSS/GPU
при длительной работе не проверялись.

Общий `ci-lint.sh` останавливается до QML на отсутствии `ruff` (также нет
`shellcheck`). Общие `ci-tests.sh unit` и `smoke` останавливаются в проверках
горячих клавиш: `test_real_validation_without_session` и `instant action search`.
Эти сценарии не менялись в рамках раздела. QML изменённых файлов, восемь
Python-тестов worker и отдельные offscreen-стенды системы, навигации, уведомлений,
полки, календаря, виджетов рабочего стола, поведения острова и бегущего текста
проверяются отдельно.
