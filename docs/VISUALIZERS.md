# Визуализаторы рабочего стола

Откройте меню рабочего стола → «Редактировать рабочий стол» → «Визуализатор».
Кнопка «Добавить» создаёт экземпляр Curtain на редактируемом мониторе.
Выберите номер экземпляра, стиль и параметры. «Показывать» скрывает только
выбранный экземпляр; «Удалить экземпляр» удаляет его настройки.

Вкладки: Look, Place, Colour, Motion, Shape. У Aura вместо Shape появляется
Field. Каталог принадлежит существующему Stage Editor. На уменьшенном рабочем
столе можно перетащить рамку, изменить размер за любой из четырёх углов или
повернуть рисунок за круглый маркер над рамкой. Escape использует существующий
порядок редактора: закрывает панель, снимает выделение, завершает редактирование.
После выхода рисунок находится на Background-слое Canvas с пустой маской ввода.
Окна приложений и их положение не меняются.

## Стили и настройки

Перенесены оригинальные `SpectrumField`, `AuraField`, GLSL-шейдеры и QSB из
[Ryoku 2befae30](https://github.com/Ryoku-dev/ryoku/tree/2befae30e0e1e8d370a8fdb4489e84be529af1bd).
Доступны Bars, Split, Dots, Segments, Wave, Ribbon, Curtain, Line, Frame,
Radial, Orb, Spiral и Aura. Миниатюры галереи используют те же GPU-компоненты
с искусственным спектром. Curtain остаётся исходным шейдерным эффектом.
Line получает подписанную PCM-волну монитора выхода.

Frame и Aura, как в Ryoku, занимают края экрана и не имеют перемещаемой рамки.
Их Place выбирает монитор. Остальные стили имеют нормализованные координаты,
ширину, высоту и угол. Across и Down обозначают центр рамки. Быстрые позиции:
центр, сброс поворота (исходная кнопка Square), полная ширина, верх, середина,
низ. Размер экрана не переписывает сохранённые доли; часть рамки всегда остаётся
доступной. Поворот выполняется вокруг её центра, изменение размера учитывает
угол поворота. Рамка управления не воспроизводит перспективу Lean X/Y.

Colour задаёт основной и второй HEX-цвет, градиент и возврат к цветам обоев.
Для Aura доступны три цвета; закрепление одного заполняет остальные текущей
палитрой. Автоматический режим использует `AccentExtractor.accent` существующей
оболочки и роли Tokens, включая смену обоев. Отдельного извлечения цветов нет.
Палитра, как у остальной Nayori, общая с основного экрана. Пространственный
анализ яркости разных участков обоев из Ryoku Scheme не переносится: он требовал
бы второго механизма анализа. Ручные цвета сохраняются при смене обоев.

Motion содержит Idle Wave, Gain, Smoothing и перспективу для поддерживающих
её стилей. FPS (30/45/60) и Adaptive общие, как в Ryoku; остальные параметры
принадлежат экземпляру. Сохранены исходные фильтры атаки/затухания, удержание
пиков, остановка таймера после установившейся тишины и адаптивные ступени
30/24 FPS при длительных задержках кадров. Idle Wave сохраняет исходное
поведение Ryoku: после затухания звука движение успокаивается до статичной
волны; это не бесконечная декоративная анимация. Отключение анимаций Nayori
останавливает движение и подписку визуализаторов на захват звука.

Shape показывает только применимые параметры: Bands, Corners, Segments,
толщину, Grows, скорость вращения, Reflection, Bloom, Mirror, Peaks и Flip.
Для Frame сохранены пики; для Line зеркало применяется к реальной волне.
У Aura Field содержит края, форму движения, эффекты, силу эффекта, режим и
скорость цвета, соединение углов, направление, длину и затухание края,
радиус и смешивание углов, частотный профиль и его силу, непрозрачность,
яркость гребня, свечение и его радиус, диапазон частот, толщину, детализацию,
реакцию на бас/высокие частоты/атаки, свечение в такт, компрессию,
чувствительность, скорость, движение в тишине, Attack/Release, материал и Reach.
Render Memory не показывается: Qt не предоставляет здесь достоверный размер
GPU-выделений, а новый SpectrumField ограничивает проход занимаемой областью;
оценка Ryoku «один полный экран на экземпляр» для этого кода неверна.

## Состояние и состав

`services/visualizer/VisualizerService.qml` создан основной сессией один раз.
Он держит ссылку на существующий SettingsService и связывает выбор со
StageSession (`visualizer:<id>`). Выбор — состояние сессии. Список хранится в
`settings.json` под `desktopVisualizers`:

```json
{
  "fps": 30,
  "adaptive": true,
  "items": [{
    "id": "viz-...",
    "output": "DP-1",
    "enabled": true,
    "style": "curtain",
    "x": 0, "y": 0.58, "w": 1, "h": 0.42,
    "angle": 0,
    "color": "", "color2": "", "gradient": false
  }]
}
```

Остальные поля и диапазоны определены `VisualizerConfig.js` по исходному
VizItem и StageVisualizerPage. Неизвестные поля списка и экземпляров
сохраняются. Повреждённые значения нормализуются, повторные ID исправляются.
Число экземпляров искусственно не ограничено. Записи отключённых мониторов
остаются в файле и возвращаются по имени выхода. Повторный запуск читает список,
не добавляя экземпляры. Запись, задержка 250 мс и обработка ошибок принадлежат
SettingsService; UI файлы не пишет.

- `surfaces/visualizer/vendor/` — исходные GPU-поля, шейдеры, математика, VizItem
  и адаптированные Motion/AuraMotion.
- `surfaces/visualizer/VisualizerView.qml` — адаптер цветов и параметров.
- `VisualizerLayer.qml` — стабильный список ID и одна подписка на аудио для слоя.
  Изменение параметров не пересоздаёт его делегаты и не прерывает перетаскивание.
- `VisualizerHandles.qml` — рамка и жесты только в редакторе.
- `VisualizerPane.qml`, `VisualizerParameter.qml` — панель на токенах Nayori.
- `services/visualizer/VisualizerParameters.js` — применимость параметров.
- `WallpaperWindow`, `OverviewWindow`, `DesktopWidgets` — показ на существующих
  поверхностях обоев, обзора и редактора. Новых layer-shell окон нет.

## Общий захват системного выхода

Новые фоновые демоны и C++-модули не нужны. Используется существующий
`AudioReaction` → `scripts/island-audio.py` → `cava` и `parec`.
Нужны Python 3, cava, parec (`libpulse` в Arch) и PulseAudio-совместимый сервер
PipeWire (`pipewire-pulse`). Эти зависимости уже есть в каталоге установщика;
при переносе пакеты не устанавливаются.

`systemConsumer` держит общий захват независимо от MPRIS. Поэтому сигналом
служит смесь приложений на выходе, включая браузеры, mpv, игры и виртуальные
выходы Easy Effects. Единственный worker на оболочку создаёт один FFT-захват
cava и один существующий PCM-монитор parec, независимо от числа экземпляров.
Микрофон не используется, громкость и маршрутизация не меняются.

Имя выхода приходит из `Pipewire.defaultAudioSink`. Оба клиента читают
`<sink>.monitor`. Смена default sink и исчезновение/возврат PipeWire очищают
старый кадр и переподключают worker. При аварии для визуализаторов сохраняются
повторные попытки с паузой до 30 секунд; зависший поток перезапускает watchdog.
Последняя отписка останавливает захват, если он не нужен музыкальной реакции.
Приложения, вручную направленные на другой, не default sink, в эту смесь не
попадают; объединение нескольких независимых физических выходов не реализовано.

Worker передаёт в строке 307 чисел: energy, beat, RMS; 48 полос для старых
музыкальных виджетов; 128 полос для визуализаторов; 128 подписанных PCM-точек.
PCM сворачивается в worker, выбирается более сильный стереоканал, чтобы
противофаза не уничтожала волну. FFT выполняет cava вне QML-потока.
48-полосный и старые короткие тестовые протоколы по-прежнему принимаются.
FPS захвата следует общему выбранному бюджету, без визуализаторов — 30.
При недоступном parec спектральные стили сохраняются, Line не подменяется
искусственной волной.

## Проверки и границы подтверждения

Регрессии включены в существующий CI: `tests/visualizers.cjs` подхватывается
unit-набором, `tests/visualizers.py` — smoke-набором. Стенды проверяют 13 стилей,
два имени выхода, независимость параметров, Field, удаление, отключение
анимаций, восстановление файла без дублей, сохранение неизвестных ключей,
подписку без MPRIS, смену выхода, ошибку worker и восстановление.
`tests/island-audio.py` дополнен проверками PCM и совместимого сворачивания FFT.
Все источники в smoke искусственные; реальные аудиоустройства не открываются.

До просьбы не запускать тесты локально прошли первоначальные
`node tests/visualizers.cjs`, `python3 tests/visualizers.py`,
`python3 tests/island-audio.py`, qmllint новых компонентов и `git diff --check`.
Это относится к промежуточной версии. После последующих правок локальные
тесты не запускались по указанию пользователя; окончательная проверка — в CI.
Полный локальный lint остановился на отсутствующем ruff, unit — на несвязанном
тесте обновления. Общий smoke был остановлен по просьбе пользователя.

Offscreen software Qt не проверяет изображение GLSL, физический ввод,
layer-shell порядок, несколько реальных экранов, DPI, воспроизведение из
Chromium/mpv/Easy Effects и GPU-нагрузку. Эти пункты приёмки, сравнение Curtain
и Aura с оригиналом на GPU и длительный замер памяти остаются неподтверждёнными.
Живая сессия при реализации не запускалась и не перезагружалась.
