# Экран блокировки и входа

Nayori использует композицию Quiet Sidebar. На основном мониторе находятся часы,
пользователь, пароль и меню питания со сном, перезагрузкой и выключением. Аватарка —
скруглённый квадрат, общий с меню «Пуск». Остальные мониторы показывают только свои обои.
Основной выход — первый в `Quickshell.screens`, как в остальной оболочке. Если он
отключён, форма переходит на первый доступный выход. Движение указателя её не переносит.

## Блокировка

`services/lock/LockService.qml` использует `WlSessionLock` (`ext-session-lock-v1`)
и `Quickshell.Services.Pam`. Поверхность создаётся на каждом выходе. Снятие
блокировки происходит после успешной проверки PAM; команды IPC для разблокировки нет.
Во время блокировки автоматическая перезагрузка QML временно отключается: в
Quickshell 0.3.2 повторное создание поверхностей при reload может нарушить работу
заблокированного экрана. После успешной авторизации восстанавливается прежняя
настройка наблюдения за файлами. Принудительно перезагружать конфигурацию во время
блокировки не следует; авария клиента оставляет сеанс закрытым.

Профиль `pam/nayori-lock` проверяет пароль текущего пользователя через `pam_unix.so`,
как локальный профиль Angel OS. Он не запускает новую сессию, не меняет `/etc/pam.d`
и не добавляет проверку отпечатка. Пароль передаётся в PAM через `PamContext`,
не через аргументы процесса, файлы или журнал. Поле очищается при отправке, смене
основного монитора и переходе ко сну.

`loginctl lock-session` обрабатывается через сигнал logind текущего сеанса.
Перед сном удерживается delay inhibitor до подтверждения `WlSessionLock.secure`.
Активная проверка пароля перед сном отменяется. При возвращении проверяется наличие
блокировки. Автоматическая блокировка по таймеру бездействия в этот модуль не входит;
её можно вызывать через существующий менеджер бездействия.

```sh
qs ipc -p /home/katamy/Projects/nayori call lock preview
qs ipc -p /home/katamy/Projects/nayori call lock closePreview
qs ipc -p /home/katamy/Projects/nayori call lock lock
```

Для Win+L добавить в блок `binds` конфигурации Niri:

```kdl
Mod+L hotkey-overlay-title="Заблокировать экран" {
    spawn "qs" "ipc" "-p" "/home/katamy/Projects/nayori" "call" "lock" "lock";
}
```

Nayori должна быть запущена. В обычном сеансе Niri `Mod` соответствует Win.

Предпросмотр доступен также в Настройки → Экран блокировки. Он не проверяет пароль,
закрывается кнопкой или Escape и не может закрыть настоящую блокировку.
Меню «Пуск» и страница питания обращаются к этому же IPC.

Плеер берётся из общего `MusicService`: тот же выбранный MPRIS-источник, обложка,
трек, исполнитель, прогресс и доступные команды воспроизведения. Без источника
карточка не создаётся. Ввод на дополнительном мониторе передаётся основному полю.
Раскладка берётся из событий Niri; кнопка раскладки переключает её через IPC Niri.

## Анимации

При блокировке фон и боковая панель появляются за 220 мс; панель смещается на 16 px.
После успешной проверки PAM панель уходит за 140 мс. Последний кадр каждого
экрана блокировки переносится на отдельную поверхность, затем плавно исчезает
поверх рабочего стола за 220 мс. `WlSessionLock` остаётся активным до подготовки
перехода на всех выходах. Сон до снятия блокировки прерывает переход и сохраняет
блокировку. При выключенных анимациях состояния меняются сразу.

Экран SDDM использует те же длительности и сохранённую настройку анимаций.
После входа рабочий стол Nayori плавно открывается за 220 мс. Это происходит один
раз при запуске оболочки; горячая перезагрузка не повторяет переход. SDDM управляет
завершением своего greeter самостоятельно, поэтому его выход не задерживает запуск
пользовательской сессии. Окно перехода рабочего стола не перехватывает ввод.

## Цвета и обои

Блокировка получает **тот же объект `Tokens.color`**, что и рабочий стол.
Динамические акцент и нейтральные поверхности не вычисляются повторно. При смене
темы меняются и цвета блокировки. Для каждого выхода используется
`WallpaperManager.wallpaper(name)` с его режимом Fill, Fit, Stretch или Center.

SDDM запускается до пользовательской оболочки и от отдельного системного
пользователя. `LoginTheme.qml` экспортирует готовые цветовые роли и копии обоев:

- `$XDG_DATA_HOME/nayori/sddm` (по умолчанию `~/.local/share/nayori/sddm`) — локальный снимок;
- `/var/lib/nayori-sddm` — снимок для SDDM, если каталог создан установщиком и принадлежит текущему пользователю.

В `theme.conf.user` сохраняются фон, поверхности, текст, акцент, текст на акценте,
граница, имя основного выхода и карта обоев. Файл публикуется атомарно после
копирования изображений. Ошибка сохраняет предыдущую конфигурацию. Пароли и команды
сеансов в снимок не входят. Каталог данных содержит только конфигурацию и изображения;
установленные файлы QML остаются под управлением root.

SDDM читает снимок при запуске экрана входа. При активной динамической теме это
последние рассчитанные цвета, при обычной — текущая палитра Nayori. До первого
экспорта используются стандартные цвета и комплектные обои. На общей машине
палитру входа публикует один выбранный при установке пользователь.

## Тема SDDM

`sddm/nayori/Main.qml` использует штатные `userModel`, `sessionModel`, `keyboard`
и `sddm.login()`. Интерфейс находится в `sddm/nayori/components/AuthView.qml`;
тот же компонент используется блокировкой. Зависимости от Quickshell в теме нет.
Музыки до входа нет. Сессии берутся из модели SDDM; команда запуска из обоев или
пользовательского снимка не читается.

Установить SDDM в Arch/CachyOS:

```sh
sudo pacman -S --needed sddm
```

Сначала проверить исходную тему, не меняя менеджер входа:

```sh
sddm-greeter-qt6 --test-mode --theme /home/katamy/Projects/nayori/sddm/nayori
```

Установить тему и выбрать её в конфигурации SDDM:

```sh
cd /home/katamy/Projects/nayori
sudo python3 scripts/install-sddm.py --owner katamy --select-theme
```

Установщик создаёт резервные копии предыдущей темы и своего drop-in. Он не запускает,
не останавливает и не переключает службы. После создания каталога опубликовать
текущий снимок обычным пользователем:

```sh
python3 services/lock/login_theme.py --sync
sddm-greeter-qt6 --test-mode --theme /usr/share/sddm/themes/nayori
```

После изменения интерфейса в репозитории обновить установленную копию темы:

```sh
sudo python3 /home/katamy/Projects/nayori/scripts/install-sddm.py --owner katamy
```

Это сохраняет выбор текущей темы и создаёт резервную копию. Перезапуска служб нет.
Меню «Питание» содержит спящий режим, перезагрузку и выключение; в предпросмотре
системные действия не выполняются. Пункты SDDM учитывают доступные ему действия.
Аватар использует ту же обрезку скруглённым квадратом с радиусом 12 px, что и меню «Пуск».

Оболочка публикует следующие изменения автоматически. Если локального снимка ещё
нет, запустить актуальную Nayori и дождаться расчёта темы.

Перед переключением проверить два выхода и масштабы в тестовом SDDM. На выходе с
сохранённым именем основного монитора показывается форма. Если имя не найдено,
используется основной монитор SDDM/Qt. Имена выходов у greeter-композитора могут
отличаться от Niri; в таком случае используется общий фон. Это следует проверить
на выбранном X11/Wayland backend SDDM до отключения прежнего менеджера входа.
Пользовательская сессия Niri остаётся Wayland независимо от backend самого greeter.

Переключение на следующий запуск системы, без остановки текущего рабочего сеанса:

```sh
sudo systemctl disable greetd.service
sudo systemctl enable sddm.service
```

Не добавлять `--now` в работающем сеансе: остановка менеджера входа может завершить
рабочий стол. Учитывать, что `/etc/sddm.conf` и другие drop-in могут переопределять
`Current=nayori`. Сценарий устанавливает только `90-nayori.conf`, чужие настройки
самостоятельно не переписывает.

Для возврата на следующий запуск:

```sh
sudo systemctl disable sddm.service
sudo systemctl enable greetd.service
```

## Проверки

```sh
python3 tests/lockscreen.py
python3 tests/lock-protocol.py
```

Первый тест проверяет форму, очистку пароля, живую смену темы, публикацию снимка,
два набора обоев, резервные копии и SDDM test mode, если greeter установлен.
Можно указать путь к распакованному greeter через `SDDM_GREETER`.

Второй запускает отдельный вложенный Niri, получает настоящий `ext-session-lock`
и проверяет отказ и успех PAM с искусственным токеном и временным `pam_exec`.
Домашний PAM и основной сеанс не меняются. Проверяются также запрет закрытия
блокировки из предпросмотра и выбор запасного основного выхода.

Аппаратный сон/возобновление, отключение реального монитора и вход с настоящим
паролем требуют отдельной ручной проверки. При аварийном завершении процесса
блокировки Wayland сохраняет защиту экрана; завершение процесса не является
способом разблокировки.

тема SDDM Angel OS и её сторонние ресурсы не копировались.
