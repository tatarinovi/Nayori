# Подтверждение действий

Nayori показывает диалог, когда polkit просит подтвердить действие. Пароль уходит в системный `PolkitAgentSession` и `polkit-agent-helper-1`. Своей проверки пароля нет, правила polkit не обходятся, и пароль не пишется в журнал, файлы или отчёты.

По умолчанию агент выключен. Оболочка не регистрируется и не останавливает чужой агент.

## Включение

Настройки → Подтверждение → «Агент подтверждения Nayori».

Ключ `polkitAgent` в `settings.json` по умолчанию `false`. Пока он выключен, объект `PolkitAgent` не создаётся. Включение записывает настройку и после проверки имени регистрирует агент на пути `/org/nayori/PolkitAgent`.

Уже запущенная оболочка читает ключ из своего `SettingsService`. Этот текст не просит перезапускать niri и не меняет автозапуск.

Статус на странице:

- «Nayori принимает запросы подтверждения» — регистрация прошла
- «Подключение к службе подтверждения» — регистрация ещё идёт
- «Модуль Quickshell Polkit недоступен» — в установленной оболочке нет модуля
- текст про занятое имя или уже существующий агент — Nayori не стала агентом сеанса

Если регистрация не удалась, выключите переключатель и включите снова. Сама она не повторяется. Пока служба ещё не ответила, объект агента не удаляется. Удаление ждёт ответа или 2,5 секунды и происходит на следующем шаге, чтобы не оборвать регистрацию.

## Другой агент

polkit разрешает одного агента на сеанс. Повторный `RegisterAuthenticationAgent` завершается отказом «An authentication agent already exists for the given subject» и прежнего агента не заменяет. Quickshell вызывает `polkit_agent_listener_register` с `POLKIT_AGENT_REGISTER_FLAGS_NONE`, без замены и без флага `fallback`.

Перед регистрацией Nayori только читает шину:

- `NameHasOwner` для `org.freedesktop.PolicyKit1.AuthenticationAgent` на пользовательской и системной шине
- если имя занято, ещё pid и имя процесса владельца

Если имя занято, `PolkitAgent` не создаётся. На polkit 128 это имя обычно никто не занимает: интерфейс висит на уникальном имени системной шины процесса-агента, а не на хорошо известном имени. Поэтому свободное имя ещё не значит, что сеанс свободен. Если служба откажет, страница покажет отказ и, когда процесс узнаётся, его имя. Узнаются `polkit-kde`, `hyprpolkit`, `mate-polkit`, `lxqt-policykit`, `xfce-polkit`, `pantheon-polkit` и `polkit-gnome`. `polkitd` и `polkit-agent-helper` в этот список не входят.

Nayori не вызывает `UnregisterAuthenticationAgent` для чужого агента и не завершает его процесс. Остановите тот агент сами, затем снова включите переключатель. Пока он работает, запросы видит он, а не диалог Nayori.

На этой машине на момент реализации имя было свободно, служба `plasma-polkit-agent.service` была неактивна, а из процессов polkit работал только `polkitd`.

## Диалог

На экране текст действия от polkit, идентификатор действия и пользователь или группа, от имени которых можно подтвердить. Если личностей несколько, выбирается одна. Смена личности начинает разговор заново и очищает поле.

Поле прячет ввод, пока polkit не попросит показать ответ. Enter подтверждает, Esc отменяет. Фокус виден. «Подтвердить» и «Отмена» — отдельные кнопки.

Неверный пароль оставляет диалог: поле очищается, можно ввести снова. Отмена и исчезновение запроса закрывают только этот запрос. Следующий в очереди Quickshell показывается после текущего, со своим текстом и пустым полем. Ответ нельзя отправить в чужой запрос.

Окно стоит на первом экране `Quickshell.screens`, как форма блокировки. Если этот выход пропал, форма переходит на первый оставшийся. Остальные мониторы показывают текст действия и строку «Подтверждение на основном мониторе», без поля пароля. Указатель диалог не переносит.

Пока сеанс заблокирован, диалог скрыт, а запрос не отменяется. После снятия блокировки поле пустое.

## Зависимости

Отдельный пакет ставить не нужно. Нужны уже установленные:

- Quickshell с модулем `Quickshell.Services.Polkit` (в 0.3.2 он собран в `qs` и связан с `libpolkit-agent-1`)
- polkit и `/usr/lib/polkit-1/polkit-agent-helper-1`
- `busctl` для чтения владельца имени

Свои привязки Python к polkit не используются. Скрипт `services/system/polkit_status.py` только читает шину и список процессов.

## Проверки

Очередь, отмена, ошибка и смена запроса проверяются без регистрации агента:

```sh
node tests/polkit-dialog.cjs
python3 tests/polkit-status.py
```

Карточка и загрузка модуля, тоже без `PolkitAgent`:

```sh
QT_QPA_PLATFORM=offscreen QT_QPA_PLATFORMTHEME=basic QT_QUICK_BACKEND=software \
  QS_DISABLE_FILE_WATCHER=1 qs -p tests/smoke/PolkitDialogSmoke.qml --no-color
```

Отдельная пользовательская шина здесь не изолирует регистрацию: `polkit_agent_listener_register` обращается к системному polkitd и к unix-сеансу процесса. Поэтому тесты не создают `PolkitAgent` и не вызывают живой запрос.

Живой запрос проверяйте только вручную и только если статус уже «Nayori принимает запросы подтверждения». Команда спросит настоящий пароль. Не запускайте её без присмотра и не кладите пароль в скрипт, файл или журнал.

```sh
pkexec true
```

Отмена закрывает диалог. Неверный пароль оставляет его для новой попытки. `true` после успешного подтверждения ничего в системе не меняет. Если статус говорит, что агент занят другим процессом, диалог Nayori не появится: запрос уйдёт тому агенту.
