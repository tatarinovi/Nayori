# Obsidian Quick Capture

В третьей вкладке Dynamic Island доступны Inbox и прежняя «Полка». Inbox сохраняет обычный UTF-8 Markdown локально. Obsidian нужен только для кнопки «Открыть», которая передаёт файл через `obsidian://open?path=…`. Сеть, Obsidian API и плагины не используются.

## Подключение Vault

Откройте **Настройки → Приложения → Obsidian Inbox**:

1. Включите Quick Capture (по умолчанию выключен).
2. Укажите существующую папку Vault: абсолютный путь или `~/…`.
3. Выберите контекст по умолчанию: Work или Personal.
4. При необходимости измените папки журналов относительно Vault. По умолчанию это `Inbox/Work` и `Inbox/Personal`. Абсолютные пути, пустые сегменты, `.` и `..` запрещены; символические ссылки внутри пути не принимаются.

Отсутствующий Vault автоматически не создаётся. Подпапки журналов создаются при первой записи. `Templates/Контекст.md` пользователь создаёт самостоятельно; Quick Capture его не читает и не изменяет.

## Горячая клавиша

Сначала узнайте абсолютный путь запущенной конфигурации Nayori. Добавьте привязку в свой блок `binds` Niri, подставив этот путь:

```kdl
Mod+Shift+I { spawn "qs" "ipc" "-p" "/absolute/path/to/nayori" "call" "inbox" "open"; }
```

Из корня репозитория команду можно проверить так:

```bash
qs ipc -p "$(pwd -P)" call inbox open
qs ipc -p "$(pwd -P)" call inbox close
```

Активный конфиг Niri автоматически не меняется. IPC открывает существующий остров на мониторе указателя, с резервным выбором по `Niri.focusedOutput`. Повторный вызов возвращает фокус уже открытому полю. Остров просит `WlrKeyboardFocus.Exclusive`, сохраняя постоянный `focusable: true`, как лаунчер. После отключения монитора используется существующий резервный экран оболочки. Блокировка закрывает ввод.

Enter сохраняет; Shift+Enter вставляет перенос; Escape закрывает. Хоткей открывает Inbox и фокусирует поле, даже если Quick Capture выключен или Vault ещё не указан. Внутри появляется подсказка; кнопка «Настроить» открывает «Приложения → Obsidian Inbox». До настройки доступен локальный черновик, запись в Vault не выполняется. При успешной записи появляется подтверждение, затем через 800 мс восстанавливаются прежние страница и раскрытие острова. Начало нового ввода отменяет этот таймер. Кнопка «Открыть» также доступна при следующем открытии Inbox в том же сеансе.

## Данные и запись

Настройки сохраняет существующий `SettingsService` в `settings.json`: `quickCaptureEnabled`, `quickCaptureVault`, `quickCaptureContext`, `quickCaptureWorkPath`, `quickCapturePersonalPath`. Неизвестные ключи сохраняются по общим правилам сервиса.

Один `QuickCaptureService` в `ShellRoot` обслуживает все мониторы через последовательный JSON Lines worker `services/quickcapture/quick_capture.py`. Отрисовка не выполняет файловых операций. Текст передаётся через stdin, без shell-команд.

Журнал называется `YYYY-MM.md` по локальным дате и времени. Запись выглядит так:

```markdown
## 2026-11-03

- **13:42** Первая строка
  вторая строка
  <!-- nayori:идентификатор-операции -->
```

HTML-комментарий не отображается в обычном просмотре Obsidian и позволяет безопасно повторить операцию после потери подтверждения. Не удаляйте его, пока операция ожидает повтора. Дата повторной операции закреплена до записи, включая переход месяца. При обычном ходе времени записи добавляются в конец. Если часы вернулись на предыдущий день, запись добавляется в существующую группу этого дня без второго заголовка.

Worker блокирует журнал между экземплярами Nayori с общим XDG state через `flock`, читает существующий текст и атомарно заменяет файл после `fsync`. Обход папок через дескрипторы с `O_NOFOLLOW` исключает выход по symlink. Незавершённые временные файлы могут остаться после аварийного завершения ОС; они имеют имя `.nayori-*` и не заменяют журнал до атомарного переключения. Другие файлы Vault не изменяются. Внешние редакторы, которые не используют эту блокировку, требуют координации: одновременное редактирование этого же журнала в Obsidian не защищено общей транзакцией.

Черновик и метаданные операций (`pending-*.json`: идентификатор, Vault, папка и дата без текста заметки) находятся в `$XDG_STATE_HOME/nayori/quick-capture/`, иначе `~/.local/state/nayori/quick-capture/`. Каталог создаётся с правами 0700, JSON и новые журналы — 0600. Каждое изменение поля отправляется worker для атомарного сохранения черновика; закрытие страницы не уничтожает сервис. Подтверждённый черновик восстанавливается после перезапуска. Между последним вводом и подтверждением worker есть короткое окно, в котором аварийное завершение процесса может потерять последние символы. Ошибка сохранения черновика отображается в Inbox.

Пока запись идёт, поле и повторное сохранение заблокированы. Ошибка не очищает текст. Неизменённую операцию можно повторить с тем же идентификатором; редактирование после ошибки начинает новую операцию. После сбоя при атомарной записи повтор использует закреплённые Vault, папку и дату; сначала восстановите доступ к этой папке. Неисправный или непрочитанный файл черновика автоматически не заменяется. При остановке worker интерфейс показывает ошибку и сохраняет текст в памяти; для восстановления службы требуется перезапустить Nayori.

## Проверки

```bash
python3 tests/quick-capture.py
bash scripts/check-quick-capture.sh
```

Unit проверяет Unicode, многострочный текст, оба контекста, создание папок и журналов, дополнение без потери записей, дату/месяц, повтор после потери ответа, 16 одновременных записей, traversal/symlink, отсутствующий Vault, сбой записи и восстановление черновика. QML offscreen проверяет фокус через существующий MorphingIsland, Enter/Shift+Enter/Escape, блокировку повтора, ошибку с сохранением текста и повторное открытие с анимацией и без неё. Проверки включены в CI unit/smoke и используют временные данные.

Offscreen не доказывает поведение layer-shell на Niri. Ручная Wayland-проверка: открыть по хоткею без движения мыши, сразу ввести текст, повторить хоткей; проверить Escape и возврат фокуса приложению; повторить на каждом из двух мониторов, с полноэкранным приложением, скрытым островом, отключением выбранного выхода и отключёнными анимациями. Проверить Work/Personal на тестовом Vault и открытие файла установленным Obsidian. Эти сценарии требуют отдельного подтверждения на реальном стенде.
