# Nayori Canvas v0.1

Canvas отображает статические обои средствами Qt Quick. Стандартный фон — предоставленное пользователем изображение `assets/wallpapers/nayori.png`, скопированное без изменения из Downloads. Noctalia для работы не нужна.

## Использование

Откройте «Настройки → Обои». Выберите монитор, изображение и режим, затем нажмите «Применить». Предпросмотр показывает черновик; до применения рабочий стол не меняется. «Стандартный фон» возвращает черновик к изображению Nayori и режиму Fill; нажмите «Применить».

Монитор выбирается переключателем над предпросмотром: «Все мониторы» включает общий фон, имя выхода (`DP-1`) отключает его и выбирает этот выход. Переключатель «Одинаковые обои на всех мониторах» связан с той же настройкой. Режим «Растянуть» показан в списке размещения только если он уже сохранён; остальные режимы работают без изменений. «Выбрать файл…» и «Стандартный фон» находятся в меню «⋯» справа от строки папки. Прокручивается только галерея; страница целиком прокручивается лишь в слишком низком окне, где галерее не хватает места на один ряд.

- Заполнить / Fill: пропорции сохраняются, края могут обрезаться.
- Вписать / Fit: изображение целиком, свободное место заполнено цветом `tokens.color.background`.
- Растянуть / Stretch: изображение занимает весь экран с изменением пропорций.
- По центру / Center: исходный размер в логических пикселях Qt; большое изображение обрезается. Предпросмотр учитывает размер выбранного монитора.

Отключите «Одинаковые обои на всех мониторах», чтобы применять выбор к отдельному выходу. Существующие индивидуальные настройки сохраняются при включении общего фона. Для нового выхода без собственной записи используется общий фон. Ключ — имя выхода (`DP-1`), а не физический серийный номер; смена имени означает новый выход. Отключение монитора не удаляет его настройки. Переключение выбранного монитора отменяет неприменённый черновик.

Обои хранятся ссылкой на исходный файл. Не удаляйте и не перемещайте его после применения. При ошибке загрузки рендерер показывает цвет фона и сообщает об ошибке в настройках. Повторный выбор доступного файла позволяет восстановить картинку. Уже загруженное изображение остаётся в памяти при удалении файла; ошибка обнаружится при следующей загрузке. Изменение содержимого файла на месте не отслеживается.

## Состав и сохранение

- `services/canvas/WallpaperManager.qml`: состояние, проверка схемы, сохранение, ошибки, выбор по имени монитора.
- `surfaces/canvas/StaticRenderer.qml`: общий рендерер рабочего стола и предпросмотра.
- `surfaces/canvas/WallpaperWindow.qml`: поверхность Wayland Background.
- `surfaces/settings/WallpaperPage.qml`: страница существующего окна настроек.
- `shell.qml`: один менеджер, `Variants` по `Quickshell.screens`, передача менеджера в настройки, IPC `canvas`.
- `surfaces/settings/Settings.qml`, `SettingsWindow.qml`: навигация, передача менеджера, высота страницы с прокруткой.
- `tests/smoke/CanvasSmoke.qml`, `scripts/check-canvas.sh`: изолированные проверки.

Файл: `$XDG_CONFIG_HOME/nayori/canvas.json`, по умолчанию `~/.config/nayori/canvas.json`.

```json
{
  "version": 1,
  "enabled": true,
  "shared": true,
  "wallpaper": {"source": "", "mode": "fill"},
  "outputs": {"DP-2": {"source": "file:///path/image.webp", "mode": "fit"}}
}
```

Пустой `source` означает встроенное изображение. Используется `Quickshell.Io.FileView`, запись атомарная; ошибка записи оставляет настройки действующими в памяти и выводит сообщение. Каталог создаётся единственным коротким `mkdir -p` через Process без shell-интерполяции. Демона и новых пакетов нет. Неизвестные поля поддерживаемой схемы сохраняются. Повреждённый файл или неизвестная версия не применяются и не перезаписываются до явного применения пользователем. Внешнее редактирование JSON требует следующей загрузки Nayori; наблюдение за файлом настроек не включено.

Постоянное хранилище Canvas находится за интерфейсом менеджера, страницы его не открывают. Другие настройки Nayori пока существуют только в памяти. Когда появится общее хранилище, переносится этот небольшой адаптер без замены UI или рендерера.

## Wayland и Niri

На каждый подключённый `ShellScreen` создаётся `PanelWindow` с namespace `nayori-canvas`, `WlrLayer.Background`, `ExclusionMode.Ignore`, `exclusiveZone: 0`. Размер задают четыре anchors; изменение геометрии обслуживает Quickshell. `Variants` удаляет поверхность при отключении выхода и создаёт при подключении.

Пустой `Region {}` задаёт пустую область ввода, `focusable: false` и `WlrKeyboardFocus.None` исключают клавиатурный фокус. В рендерере нет обработчиков мыши или клавиатуры. PNG/JPG/WebP декодирует установленный Qt; `Image` загружает асинхронно, учитывает ориентацию и не держит общий кэш изображений. Это не видеорендерер: GIF, видео, сцены, шейдеры и параллакс не поддерживаются контрактом v0.1.

В Overview фон уменьшается вместе с каждым рабочим столом. Промежутки между столами и backdrop остаются под управлением Niri. Отдельная картинка backdrop потребовала бы дополнительной поверхности и пользовательского `layer-rule` с `place-within-backdrop true`; v0.1 она не нужна, конфигурация Niri не изменялась. Чужие фоновые поверхности могут перекрывать Canvas в зависимости от порядка отображения; Canvas не останавливает их и не управляет их настройками.

Источники: [Quickshell FileView](https://quickshell.org/docs/v0.3.1/types/Quickshell.Io/FileView/), [Variants](https://quickshell.org/docs/v0.3.1/types/Quickshell/Variants/), [Niri Overview](https://github.com/niri-wm/niri/blob/main/docs/wiki/Overview.md). Локальные qmltypes и работающая сессия имеют приоритет над документацией другой версии.

## Контракт рендерера и v0.2

Текущий вход рендерера: `source: url`, `mode: string`, `backgroundColor: color`, геометрия родителя; `nativeScale` используется только в предпросмотре. Выход: `loaded: bool`, `failed: bool`. Владение поверхностью, жизненным циклом монитора и input region остаётся у WallpaperWindow; конфигурацией и ошибками — у менеджера. Рендерер не пишет настройки и не обращается к IPC Niri.

Для v0.2 сначала добавить версию схемы и явный `kind` (`static`, позднее `animated`/`qml-scene`), затем выбирать компонент через Loader внутри существующего окна. Новому рендереру понадобятся состояния loading/ready/error, сигнал с причиной ошибки, active/paused и освобождение ресурсов при выгрузке. Анимации должны останавливаться вне видимости и при отключении монитора; нужны бюджеты CPU/GPU/памяти и тесты DPI.

Многослойная композиция, частицы, персонаж, параллакс и реакции на курсор принадлежат будущему компоненту сцены. Интерактивность потребует отдельного явного контракта: разрешённые области ввода, координаты курсора и политика фокуса. Нельзя просто заменить пустую маску на весь экран. Загружаемый QML выполняет код, поэтому импорт произвольных QML-сцен потребует решения о доверии. В v0.1 этих возможностей нет.

## Проверено 25 октября 2026

Машина: Quickshell 0.3.2, Qt base/declarative 6.12.0, qt6-imageformats 6.12.0, Niri 26.04. `qmllint` из PATH оказался Qt 5 (1.0); проверка использует `/usr/lib/qt6/bin/qmllint`. У qmltypes Quickshell есть известные для этой проверки пробелы: PanelWindow помечен не создаваемым, тип screen не описывает name. Эти две категории отключены в линтере; реальные поверхности проверены в Wayland.

Фактически выполнены:

- Загрузка Nayori горячей перезагрузкой существующего процесса, без его остановки. Во время записи файлов были временные ошибки разрешения QML-типов; повторная загрузка после записи завершилась `Configuration Loaded`.
- `niri msg --json layers`: Background `nayori-canvas` на DP-1 и DP-2, keyboard_interactivity None; четыре существующих острова остались Overlay.
- Снимки рабочего стола, страницы «Обои» с присланной картинкой и Overview. В Overview картинка находится внутри рабочих столов, острова остаются сверху. Обычный режим восстановлен.
- Запись настоящего `~/.config/nayori/canvas.json` со стандартным изображением, shared=true, Fill; следующая горячая загрузка восстановила его.
- Изолированный smoke: декодирование PNG/JPG/WebP, перебор четырёх режимов, запись на диск и чтение другим экземпляром менеджера, выбор по выходу и общий фон, fallback нового выхода, ошибка отсутствующего изображения, создание Settings с активной страницей обоев. Это проверка загрузки и свойств, не попиксельная проверка всех режимов.
- Qt 6 qmllint для новых компонентов и `git diff --check`.

Запуск: `bash scripts/check-canvas.sh`. Скрипт использует уже установленный ImageMagick только для тестовых JPG/WebP, создаёт данные в `/tmp`; runtime Canvas от ImageMagick не зависит. В sandbox offscreen-тест сообщает о невозможности открыть IPC-сокет; тест не использует IPC. Предупреждение об отсутствующей картинке ожидаемо. Успех определяется маркером `CANVAS_SMOKE_PASS`.

Осталось проверить вручную без изменения Niri:

1. Выбрать файл через диалог, проверить предпросмотр, каждый режим и применение; повторить с пробелами и кириллицей в пути.
2. Назначить разные изображения двум выходам; переключить рабочий стол, проверить фон и доступность островов.
3. В удобный момент физически отключить и подключить второй монитор: его запись должна сохраниться, первый фон продолжить работу.
4. Закрыть настройки и проверить клики и прокрутку в приложениях, сочетания клавиш, Bottom Bar и Dynamic Island. Статическая маска и отсутствие клавиатурного фокуса проверены в коде/IPC, полноценного теста указателя не было.
5. При следующем обычном запуске Nayori проверить восстановление. Действующая оболочка специально не перезапускалась; чтение с диска и горячее восстановление проверены отдельно.

## Безопасное отключение

Снимите «Показывать фон Canvas» и нажмите «Применить»: исчезнут только фоновые окна Canvas. Остальная оболочка работает дальше. Для аварийного запуска используйте `NAYORI_CANVAS_DISABLED=1 qs -p /home/katamy/Projects/nayori`; это не меняет сохранённый enabled. Не запускайте второй экземпляр поверх уже работающего. Для отключения в коде можно удалить только блок Variants Canvas в shell.qml. Никаких действий с Noctalia, greetd, Niri или автозапуском не требуется.
