# Bluetooth

Nayori использует один сервис `BluetoothService`, принадлежащий `ShellRoot`. Меню трея и страница «Устройства → Bluetooth» работают с одним адаптером и обновляются без повторного открытия. SNI-элементы системного трея продолжают обслуживаться отдельным `Tray`.

## Управление

- ЛКМ по значку Bluetooth открывает меню. Значок различает выключенное, включённое, недоступное состояние и подключённые устройства.
- Bluetooth включается переключателем-слайдером в первой строке меню, рядом с заголовком. При отсутствии адаптера показано пояснение; при аппаратной блокировке — сообщение о переключателе/rfkill.
- Подключённые, сохранённые и обнаруженные устройства показаны отдельными группами с увеличенными заголовками. Счётчик подключений и имя адаптера в меню не выводятся. Справа от названия находятся иконки подключения/отключения и удаления сопряжения. Подсказки поясняют действия. Удаление требует отдельного подтверждения.
- Достоверный заряд показан в списке только для подключённого устройства с `batteryAvailable` и значением `battery` в диапазоне 0–1. Рядом с иконкой Bluetooth в трее у каждого такого устройства есть тонкий вертикальный бар, без цифр. Название и процент появляются при наведении. При отсутствии сведений индикатор не создаётся.
- Поиск начинается только кнопкой «Найти устройства». Его можно остановить вручную; он завершается при закрытии меню/страницы или через 60 секунд. Nayori освобождает только собственную сессию поиска и не останавливает поиск других клиентов BlueZ.
- Во время операции повторные действия заблокированы, показано состояние выполнения. Ошибки D-Bus отображаются в интерфейсе. При сопряжении Nayori предлагает подтвердить код, ввести PIN/ключ или набрать отображаемый код на устройстве.
- Иконка шестерёнки в заголовке, рядом с переключателем, открывает страницу Bluetooth в настройках Nayori.

ПКМ по значку → «Скрыть иконку» сохраняет `bluetoothIconVisible: false` через общий `SettingsService` в `settings.json`. Вернуть иконку можно переключателем «Показывать Bluetooth в системном трее» на странице Bluetooth. Это не изменяет питание адаптера. По умолчанию значок виден.

## Архитектура и зависимости

`services/system/BluetoothBackend.qml` динамически загружает установленный `Quickshell.Bluetooth`. Нативные модели передают изменения адаптера, устройств, соединений и батареи через сигналы BlueZ. Если модуль отсутствует, сервис показывает сообщение, не прерывая загрузку оболочки. Используется `Bluetooth.defaultAdapter`; интерфейс выбора нескольких адаптеров пока не предусмотрен.

Текущий API Quickshell предоставляет методы устройств, но не сообщает вызывающему QML-коду результат асинхронных операций и не предоставляет UI агента сопряжения. Эти возможности дополняет `scripts/bluetooth-bridge.py`: один процесс Python с **PyGObject/Gio** (`python-gobject` в Arch/CachyOS, `python3-gi` в Debian/Ubuntu). Он вызывает BlueZ на системной D-Bus-шине, возвращает результаты через JSON lines и регистрирует `org.bluez.Agent1` только для своего клиента с возможностью `KeyboardDisplay`. Системный агент по умолчанию не заменяется; входящие запросы вне инициированного Nayori сопряжения отклоняются.

Соединение bridge остаётся открытым, пока работает оболочка: это необходимо для владения сессией обнаружения BlueZ. При завершении процесса BlueZ освобождает сессию и регистрацию агента. Остановка поиска доступна даже во время подключения/сопряжения. Постоянного сканирования, опроса состояния и запуска `bluetoothctl` нет. Таймаут отдельного D-Bus-вызова — 90 секунд. Права на операции определяются BlueZ и политиками системы; Nayori не изменяет службы или системные разрешения.

Нужны установленный модуль Quickshell Bluetooth, BlueZ и доступная системная D-Bus-шина. При недоступной шине или отсутствующем PyGObject кнопки операций отключаются с пояснением. После исправления зависимостей нужно перезапустить Nayori.

Спецификации: [Quickshell BluetoothDevice](https://master.quickshell.org/docs/types/Quickshell.Bluetooth/BluetoothDevice), [BlueZ Device API](https://bluez.readthedocs.io/en/latest/device-api/), [Adapter API](https://bluez.readthedocs.io/en/latest/adapter-api/), [Agent API](https://bluez.readthedocs.io/en/latest/agent-api/).

## Проверки

```sh
dbus-run-session -- python3 tests/bluetooth.py
python3 tests/settings.py
python3 tests/settings-window.py
python3 tests/panel-modes.py
```

Bluetooth-тест подменяет системную шину изолированной D-Bus-сессией с тестовым BlueZ и запускает настоящие Quickshell-модели, QML-интерфейс и bridge. Проверяет питание, подключение/отключение, блокировку повторной операции, достоверный заряд, обнаружение нового устройства, остановку поиска, Agent1 с подтверждением кода, удаление сопряжения, ошибки подключения, исчезновение адаптера и восстановление видимости новым экземпляром SettingsService. Физический адаптер не используется.

Для снимка интерфейса теста: `NAYORI_BT_PREVIEW=/tmp/bluetooth.png dbus-run-session -- python3 tests/bluetooth.py`.

На рабочем оборудовании дополнительно проверьте поиск и сопряжение наушников/клавиатуры (включая PIN), батарею, аппаратную блокировку, отключение адаптера и перезапуск оболочки. Изолированный тест не подтверждает радиосвязь и политики доступа конкретной системы.
