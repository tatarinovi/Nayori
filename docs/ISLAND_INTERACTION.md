# Лиса и уведомления Dynamic Island

Лиса сохраняет лежащий силуэт. Её поведение рассчитывает чистый контроллер `services/island/Behavior.js`: дыхание и хвост по CPU, музыкальные акценты, взгляд и маркер работают отдельными каналами. Музыка управляет хвостом, наведение — направлением головы; остальные движения продолжаются вместе с ними. CPU сглаживается с постоянной времени 1 с, энергия — 80 мс при нарастании и 250 мс при спаде, удары — импульсом 30/220 мс. В reduced motion лиса неподвижна, маркер остаётся.

MPRIS определяет воспроизведение. Один процесс `cava` анализирует монитор текущего системного выхода через совместимость PulseAudio в PipeWire. Поэтому в реакцию могут попадать звуки других приложений, пока музыка воспроизводится. При смене выхода анализатор переподключается; при ошибках действует ограниченный повтор с задержкой. Без данных звука хвост снова зависит от CPU. Нужны уже установленные `cava`, Python 3 и работающий PipeWire с PulseAudio-совместимым сервером.

## Уведомления

Обычный запуск Nayori не занимает D-Bus-сервис уведомлений. Явное включение:

```sh
NAYORI_NOTIFICATIONS=1 qs -p /home/katamy/Projects/nayori
```

Если сервис уже занят, Nayori оставляет его владельцу и выводит диагностику. Noctalia и автозапуск не меняются. Приём работает во вспомогательном процессе: проверка до запуска и проверка владельца после регистрации учитывают гонку за D-Bus-имя. При конфликте процесс завершается, чтобы Quickshell не перехватил имя позже своим автоматическим повтором регистрации.

В свёрнутом острове каждое уведомление заменяет обычное содержимое на 5 секунд. Остальные ждут в очереди. Раскрытие приостанавливает показ; открытие страницы «Уведомления» отмечает записи просмотренными и исключает их из очереди. Новые поступления на открытой странице сразу считаются просмотренными. Завершение компактного показа само по себе не снимает маркер непрочитанного.

Прочтение, закрытие приложением, удаление пользователем и завершение компактного показа — разные состояния. Закрытые уведомления остаются в списке с недоступными действиями. Удалённые не возвращаются при обновлении приложением. История приложения хранится только в памяти и теряется при перезапуске конфигурации; отдельного файла истории нет. Вспомогательный процесс передаёт события через поток вывода, который Quickshell также записывает в свой журнал в runtime-каталоге.

«Главная» и «Уведомления» находятся в одной строке навигации. Переключение — горизонтальный переход на 220 мс, в reduced motion — сразу. Колесо вниз открывает уведомления; колесо вверх возвращает на главную. Длинный список сначала прокручивается внутри страницы; у верхней границы колесо вверх переключает страницу. Дробные события колеса накапливаются, повторное переключение ограничено длительностью перехода.

Обе страницы используют общие `IslandLabel`, `IslandAction` и `IslandCard`: типографика, кнопки, поверхности и скругления соответствуют существующему Anime Editorial оформлению.

## Проверки и ручной стенд

```sh
bash scripts/check-island.sh
qs -p /home/katamy/Projects/nayori/IslandBehaviorSmoke.qml
```

Стенд позволяет менять CPU, energy, playing, reduced motion, подавать beat и искусственное наведение, добавлять уведомления и вручную продвигать время очереди на 5 секунд. Реальные CPU polling, `cava` и сервер уведомлений в нём не запускаются. Для автоматического сценария используется `NAYORI_ISLAND_AUTOTEST=1`.

Проверки контроллеров выполняются в Node.js, QML — в offscreen-режиме. `AudioReactionSmoke.qml` проверяет поток данных, переподключение к другому выходу, задержки повторов и остановку при паузе на искусственном процессе. Тесты D-Bus запускаются только через `dbus-run-session` на отдельной шине: приём, обновление, закрытие, занятое имя, гонка регистрации и вся цепочка до модели с обратным удалением через IPC.

Автоматический визуальный сценарий сохраняет снимки в `/tmp/nayori-island-preview.png`, `/tmp/nayori-island-compact.png` и `/tmp/nayori-island-home.png`.

Нативное наведение и физическое колесо Wayland, захват реального аудиовыхода и работа с аппаратным переключением устройств требуют проверки в рабочей сессии. Изолированные проверки их не заменяют. Полная оболочка с PanelWindow не запускается через offscreen; отдельные компоненты проверяются стендами.

После исправления локальных типов страницы подтверждена успешная горячая перезагрузка действующего Wayland-экземпляра Nayori: журнал `3maxeignt` сообщает `Configuration Loaded`. Загрузка всей оболочки в рабочей сессии подтверждена; нативные жесты и реальный аудиосигнал отдельно не проверялись.

`IslandWheelSmoke.qml` отправляет события колеса через QtTest в окно целого MorphingIsland: вертикальное и горизонтальное переключение над навигацией, накопление дробных шагов, прокрутка длинного списка и возврат через заголовок при прокрученном списке. У навигации и содержимого отдельные WheelHandler с поддержкой мыши и тачпада; пиксельные дельты учитываются, если угловые отсутствуют.
