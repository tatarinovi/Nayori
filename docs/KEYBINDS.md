# Горячие клавиши

Раздел «Устройства → Горячие клавиши» (`shortcuts`, прежний индекс 13)
объединяет конфигурацию Niri, зарегистрированные IPC-действия Nayori и явно
заданные `map` Kitty. Компактная таблица показывает действие, комбинацию и источник. Кнопка карандаша
открывает редактор; «⋯» раскрывает категорию, состояние, путь файла, причины
конфликтов и действия сброса/отключения/удаления. Категории и фильтры закреплены
над отдельным прокручиваемым списком, счётчики конфликтов — под ним. Поиск обновляется при вводе, фильтры работают
по категории, источнику и конфликтам. Категории появляются по обнаруженным действиям.

## Источники и хранение

`services/keybinds/keybinds.py` содержит отдельные `NiriAdapter` и `KittyAdapter`;
`KeybindService.qml` связывает их с настройками по JSON Lines. Контроллер настроек
владеет одним сервисом, страница не владеет файлами. Чтение ничего не применяет.

Niri читается из `NIRI_CONFIG`, иначе `$XDG_CONFIG_HOME/niri/config.kdl`, иначе
`~/.config/niri/config.kdl`. Поддерживаются относительные, абсолютные и домашние
include, вложенные подключения и отсутствующие `optional=true`. Порядок включает
позицию include: поздний блок `binds` переопределяет ранний. Переопределённые
записи остаются видимыми, но исключаются из активных конфликтов. Подключение
одного файла несколько раз не создаёт несколько редакторов одного узла.
Защищённые фрагменты существующего редактора (`noctalia.kdl`, акцент и обзор)
показываются только для чтения.

Nayori распознаётся по известным IPC-целям в `spawn`, а также по простой команде
`spawn-sh`, которую можно разобрать без исполнения. Произвольный shell-скрипт не
анализируется как IPC. Доступные действия без бинда появляются с состоянием
«Не назначено». Сочетание для такого действия создаёт обычный Niri-бинд.
Нажатие Super обслуживает существующий `SuperTap`: его можно отключить или
включить через `superTapEnabled` в SettingsService. Для другого сочетания
создайте действие Nayori → Пуск; исходный Super при необходимости отключается
отдельно. Во время записи SuperTap приостанавливается.

Kitty читает `$XDG_CONFIG_HOME/kitty/kitty.conf` и обычные include. Область действия
— окно Kitty. Поддержка только для чтения; стандартные встроенные комбинации,
шаблоны include, условные map с опциями и многошаговые сочетания не объявляются
полностью обнаруженными. `kitty_mod` без проверки не заменяется предполагаемым
значением. Терминалы других форматов, произвольные конфиги лаунчеров и системных
утилит автоматически не редактируются. Их глобальные запуски, заданные в Niri,
видны как обычные бинды.

## Запись и пользовательские действия

Редактор держит черновик до «Сохранить». Комбинацию можно записать с клавиатуры
или ввести именами XKB: Super, Ctrl, Alt, Shift, Mod5, функциональные, цифровой
блок, мультимедиа и допустимые Niri клавиши мыши. libxkbcommon, уже требуемая Qt
и Niri, проверяет имена; новые пакеты не нужны. Записывается логическая клавиша
текущей раскладки, не физический scan code. Латинские клавиши и символы другой
раскладки Niri сопоставляет по своим правилам. Мышь вводится вручную.

На время записи включается штатный Quickshell `ShortcutInhibitor` для окна
настроек. При отсутствии активного перехвата показано предупреждение; ввод
вручную остаётся доступным. `allow-inhibiting=false`, VT и другие системные
комбинации могут сработать независимо от перехвата. Esc отменяет запись,
таймер 15 секунд, потеря фокуса поля и закрытие окна освобождают её.

Пользовательский бинд создаётся для запуска программы с аргументами, команды,
URL HTTP/HTTPS, известного действия Nayori или поддерживаемого действия Niri.
Команды преобразуются в `spawn` с отдельными аргументами; shell нужен только
при явном `sh -c`. Проверка и редактирование команд ничего не запускают.
Для существующего пользовательского бинда доступны изменение комбинации,
названия, категории, типа и параметров действия, сброс, временное отключение
и удаление с подтверждением. Произвольные действия Niri при смене комбинации
сохраняются буквально.

Управляемые метаданные (название, категория, исходная комбинация) хранятся
комментарием `// nayori-keybind:<base64 JSON>` рядом с узлом. Это не второй
список активных биндов: исполняемое состояние остаётся в Niri. Отключение —
штатный `/-` перед узлом. Сброс возвращает комбинацию до первой правки этим
менеджером; универсальных заводских значений для чужой конфигурации нет.

## Безопасное сохранение

Запись выполняет существующий `services/system/niri_config_apply.py`.
Адаптер готовит минимальную замену имени узла и проверяет SHA-256 всех
прочитанных файлов. Устаревший снимок, непрочитанный include или неизвестный
KDL-фрагмент останавливает запись. Новый бинд добавляется в существующий
корневой блок `binds`, либо в новый блок, если такого ещё нет. Include не
переписываются. Комментарии, свойства, аргументы и несвязанные настройки
при обычной смене комбинации сохраняются, включая переводы строк исходного файла.

Перед записью создаётся резервная копия рядом с изменяемым файлом, затем файл
заменяется атомарно и выполняется `niri validate -c <корневой файл>`. Ошибка
проверки возвращает исходные байты, а интерфейс показывает причину. Только
после успешной записи отдельный запрос выполняет поддерживаемый
`niri msg action load-config-file`. Ошибка перечитывания показывается отдельно:
валидная запись остаётся на диске. Niri также наблюдает за подключёнными файлами.
Чтение, запуск страницы и проверка команды живую сессию не перечитывают.

Новые назначения, которые занимают активную глобальную комбинацию Niri,
отклоняются с названием занятого действия. Сначала нужно освободить комбинацию.
Отключение/удаление пользовательского бинда не удаляет другие пользовательские
действия. При включении отключённого бинда свободность проверяется снова.

## Конфликты

Сравнение учитывает порядок/регистр модификаторов, Ctrl/Control, Super/Win,
Mod5/ISO_Level3_Shift и XKB-имена клавиш. `Mod` берётся из `input mod-key`;
без явной настройки интерфейс предлагает Super для обычного сеанса и Alt для
Niri в окне. Это выбор для проверки, не новая запись системной настройки.

Подтверждённый конфликт — одинаковые активные глобальные комбинации в одном
блоке Niri, в том числе команды разных источников. Одинаковые назначения,
переопределённые поздним блоком, не считаются двумя активными действиями.
Глобальное сочетание и локальное Kitty, нажатие против SuperTap, а также
Ctrl+Alt+F1…F12 помечаются как возможное пересечение. Отключённые назначения и
локальные сочетания двух разных приложений не создают глобального конфликта.
В предупреждении указаны оба действия, источники, причина и способ исправления.
Счётчики подтверждённых и возможных пересечений разделены.

Проверка не моделирует всю XKB-раскладку, динамические портальные регистрации,
режимы сторонних приложений и конфиги неизвестного формата. Полное отсутствие
пересечений со всем программным обеспечением не гарантируется.

## Приложения по умолчанию

На странице «Приложения по умолчанию» добавлены пять ролей для сочетаний:
терминал, браузер, файловый менеджер, редактор и заметки. Это desktop ID,
записываемые существующим SettingsService. `preferredTerminal` и
`preferredFileManager` общие с «Пуск»; новые ключи — `preferredBrowser`,
`preferredEditor`, `preferredNotes`. Неизвестные ключи настроек сохраняются.
Существующая секция ассоциаций xdg-mime сохраняется отдельно по своему назначению.

Цель IPC `apps` предоставляет методы `terminal`, `browser`, `files`, `editor`,
`notes`. ShellRoot запускает выбранный desktop entry через существующий Apps.
Вызов IPC является действием пользователя; чтение настроек приложения не запускает.
В редакторе обнаруженного app-бинда можно явно заменить его `spawn` на роль
приложения по умолчанию. Меняется только выбранный узел действия, свойства и
внешние комментарии сохраняются. Выбор приложения на странице настроек сам по
себе не переписывает произвольные пользовательские команды Niri.

## Ryoku: исследование и лицензия

Референс изучен в локальном checkout `Ryoku-dev/ryoku` на коммите
`f7197d72de8a21e44b0bea922bdd915f28f6b327`:

- `ryoku/hub/quickshell/pages/KeybindsPage.qml`: список, Apps/Custom, черновик,
  запись через ShortcutInhibitor и ограничение времени.
- `ryoku/hub/quickshell/Combos.js`: нормализация и поиск повторяющихся комбинаций.
- `ryoku/hub/backend/keybinds.go`: единая модель от провайдера compositor.
- `ryoku/hub/backend/apps.go`: роли terminal/browser/files/editor/notes.
- `ryoku/wm/niri/config_binds.go`: разрешение назначений и генерация общего
  набора биндов Niri из каталога и store.

Структура списка, роли приложений и запись с inhibitor использованы как
UX-референс. Генерация полного набора Ryoku не переносилась: Nayori должна
сохранять произвольные пользовательские KDL-файлы. Использованы существующие
SettingsService, Apps и редактор конфигурации Nayori. Код и ресурсы Ryoku не
копировались. Ryoku указывает GPL-3.0 в
[LICENSE](https://github.com/Ryoku-dev/ryoku/blob/main/LICENSE) и
[NOTICE](https://github.com/Ryoku-dev/ryoku/blob/main/NOTICE); изменение лицензии
Nayori для этой реализации не выполнялось.

Правила сверены с документацией Niri:
[сочетания](https://niri-wm.github.io/niri/Configuration:-Key-Bindings.html),
[include и переопределение](https://niri-wm.github.io/niri/Configuration:-Include.html).

## CI и ручная проверка

В `scripts/ci-tests.sh` подключены:

- unit: `python3 tests/keybinds.py` — include, минимальная правка, копии,
  восстановление при отказе валидации/записи, устаревшая версия файла,
  отключение/включение/удаление, области конфликтов и настоящий `niri validate`
  исключительно на временных конфигурациях.
- unit: `tests/keybind-recorder.cjs` — модификаторы, keypad, функциональные,
  мультимедиа и нелатинские клавиши; запускается общим циклом `tests/*.cjs`.
- smoke: `python3 tests/keybinds.py --smoke` — offscreen-страница, поиск,
  фильтры, черновик/подтверждение, создание, отключение и удаление.
  Niri подменён mock-командой; живые сокеты удалены из окружения.

По просьбе пользователя тесты оставлены для CI и локально не запускались.
Локально проверялись только синтаксис Python/JS, qmllint изменённых QML и diff.
Проверка реального физического ввода, предоставления inhibitor, нескольких
мониторов и перезапуска системы требует отдельной разрешённой Wayland-сессии.
