# Настройки Nayori

Settings Service создаётся в `shell.qml` и работает независимо от окна настроек. Он читает конфигурацию при запуске, немедленно применяет пользовательские изменения и сохраняет их после 250 мс без новых изменений. Один таймер обслуживает все настройки. Город меняется только по кнопке «Применить».

Файл: `$XDG_CONFIG_HOME/nayori/settings.json`, либо `~/.config/nayori/settings.json`, если переменная не задана. Ручные правки вступают в силу после перезапуска. Пример значений по умолчанию:

```json
{
  "version": 1,
  "autoHideTop": false,
  "autoHideApps": false,
  "autoHideWorkspaces": false,
  "autoHideStatus": false,
  "hideSecondaryIsland": false,
  "topReserved": 0,
  "bottomReserved": 0,
  "animationsEnabled": true,
  "weatherCity": ""
}
```

Отступы ограничены диапазоном 0–200 px и округляются до ближайшего значения с шагом 4. Пробелы по краям города удаляются. Отсутствующие поля и известные поля неверного типа получают значения по умолчанию. Неизвестные поля, включая вложенные структуры, сохраняются при записи. Форматирование JSON при этом может измениться.

До окончания чтения запись запрещена. Отсутствующий файл создаётся при первом изменении. Запись атомарная; при ошибке значения остаются активными в сеансе, а интерфейс предлагает повторить запись. Полное сообщение в нижней строке доступно при наведении, если оно не помещается.

При неподдерживаемой версии запись заблокирована: изменения действуют только в сеансе. Используйте совместимую версию Nayori или вручную перенесите нужные значения в поддерживаемую схему. При ошибке чтения проверьте доступ к файлу и перезапустите оболочку.

Повреждённый файл автоматически не заменяется. Кнопка «Восстановить настройки» сначала сохраняет его исходные байты в уникальном файле `settings.json.backup-*` в том же каталоге. Копия создаётся с доступом только для владельца; запись и синхронизация копии должны завершиться успешно перед заменой конфигурации. Затем сохраняются текущие рабочие значения. Ошибка создания копии блокирует замену. Восстановление использует Python 3.

`flush(true)` выполняет синхронную запись ожидающих изменений. Он вызывается при уничтожении сервиса через `Component.onDestruction`; сценарий штатного `Qt.quit()` проверяется тестом. Закрытие окна настроек не вызывает flush и не уничтожает сервис. Завершение через SIGKILL, авария или иной выход без уничтожения QML-компонентов не гарантируют сохранение последних 250 мс изменений.

## Разделение интерфейса

`Settings.qml` — встраиваемый контейнер навигации и страниц. Он получает значения через свойства и передаёт пользовательские действия сигналами. Страницы не обращаются к сервису, Dynamic Island, экрану или слоям Wayland. Привязки обновляют интерфейс из сервиса; обработчики пользовательских действий обновляют сервис. Программное изменение свойств не запускает обратную запись.

Текущее `SettingsWindow` отвечает за размещение, ограничения размеров и механизм отображения. В будущем его можно заменить обычным окном Niri, сохранив контейнер и страницы. На этом этапе новое окно и командный интерфейс не создаются.

`WallpaperManager` независимо хранит обои в `canvas.json`. Имя и аватар берутся из системы. Навигация и состояние открытых окон не сохраняются.

## Проверки

```sh
python3 tests/settings.py
bash scripts/check-island.sh
bash scripts/check-canvas.sh
```

Проверки настроек используют временные каталоги и отдельный процесс Quickshell с offscreen-платформой. Пользовательская конфигурация не изменяется.
