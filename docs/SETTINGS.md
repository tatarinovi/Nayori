# Настройки Nayori

Settings Service создаётся в `shell.qml` и работает независимо от окна настроек. Он читает конфигурацию при запуске, немедленно применяет пользовательские изменения и сохраняет их после 250 мс без новых изменений. Один таймер обслуживает все настройки. Город меняется только по кнопке «Применить».

Файл: `$XDG_CONFIG_HOME/nayori/settings.json`, либо `~/.config/nayori/settings.json`, если переменная не задана. Ручные правки вступают в силу после перезапуска. Пример значений по умолчанию:

```json
{
  "version": 1,
  "autoHideTop": false,
  "autoHideApps": false,
  "autoHideWorkspaces": false,
  "autoHideStatus": false,
  "hideSecondaryIsland": false,
  "topReserved": 0,
  "bottomReserved": 0,
  "animationsEnabled": true,
  "accentMode": "default",
  "manualAccent": "#C0AFD1",
  "weatherCity": "",
  "weatherRefreshMinutes": 15
}
```

Отступы ограничены диапазоном 0–200 px и округляются до ближайшего значения с шагом 4. Пробелы по краям города удаляются. `weatherRefreshMinutes` задаёт интервал фонового обновления погоды в минутах: целое число от 1 до 180, по умолчанию 15. Неверные значения заменяются значением по умолчанию. Изменение интервала применяется сразу; открытие острова не запускает загрузку погоды. Отсутствующие поля и известные поля неверного типа получают значения по умолчанию. Неизвестные поля, включая вложенные структуры, сохраняются при записи. Форматирование JSON при этом может измениться.

До окончания чтения запись запрещена. Отсутствующий файл создаётся при первом изменении. Запись атомарная; при ошибке значения остаются активными в сеансе, а интерфейс предлагает повторить запись. Полное сообщение в нижней строке доступно при наведении, если оно не помещается.

При неподдерживаемой версии запись заблокирована: изменения действуют только в сеансе. Используйте совместимую версию Nayori или вручную перенесите нужные значения в поддерживаемую схему. При ошибке чтения проверьте доступ к файлу и перезапустите оболочку.

Повреждённый файл автоматически не заменяется. Кнопка «Восстановить настройки» сначала сохраняет его исходные байты в уникальном файле `settings.json.backup-*` в том же каталоге. Копия создаётся с доступом только для владельца; запись и синхронизация копии должны завершиться успешно перед заменой конфигурации. Затем сохраняются текущие рабочие значения. Ошибка создания копии блокирует замену. Восстановление использует Python 3.

`flush(true)` выполняет синхронную запись ожидающих изменений. Он вызывается при уничтожении сервиса через `Component.onDestruction`; сценарий штатного `Qt.quit()` проверяется тестом. Закрытие окна настроек не вызывает flush и не уничтожает сервис. Завершение через SIGKILL, авария или иной выход без уничтожения QML-компонентов не гарантируют сохранение последних 250 мс изменений.

## Разделение интерфейса

`Settings.qml` — встраиваемый контейнер навигации и страниц. Он получает значения через свойства и передаёт пользовательские действия сигналами. Страницы не обращаются к сервису, Dynamic Island, экрану или слоям Wayland. Привязки обновляют интерфейс из сервиса; обработчики пользовательских действий обновляют сервис. Программное изменение свойств не запускает обратную запись.

`SettingsWindow` — обычное `FloatingWindow`, создаваемое контроллером на уровне оболочки. Это не LayerShell и не дочернее окно Dynamic Island. Niri управляет его тайловым размещением, мониторами, фокусом, изменением размеров и максимизацией. Запрашиваемый размер — 1100×760 логических px, минимум — 720×560. Фактический размер тайлового окна определяет композитор. Боковая колонка занимает 232 px, при ширине менее 960 px — 184 px. Страницы прокручиваются, основной текст не уменьшается при сужении окна.

`SettingsController` создаёт один экземпляр интерфейса по запросу, затем показывает и скрывает его. Стандартное закрытие сбрасывает состояние открытия и сохранённый Niri window ID. Если QML-объект уничтожен, следующий запрос создаёт новый. Для регистрации проверяются PID текущего процесса, app_id и заголовок, затем активация использует точный Niri window ID и повторную проверку PID. Закрытые ID исключаются из повторного выбора. При недоступности Niri используется стандартный запрос активации Qt.

app_id всего экземпляра Quickshell — `nayori`, заголовок окна — `Nayori Settings`. Окно сохраняет выбранный раздел в пределах процесса. После полного перезапуска оболочки оно закрыто и открывается только по запросу. Открытие лаунчера или острова не закрывает настройки. Escape сначала обслуживает вложенные меню и диалоги; необработанный Escape закрывает окно, не завершая Nayori.

## Страница «Панель задач»

Страница `panels` состоит из двух карточек (`SettingsCard`). «Общие параметры»: главный переключатель автоскрытия (включает и выключает `autoHideTop/Apps/Workspaces/Status` разом), чипы для автоскрытия каждого острова отдельно, отступы `topReserved` и `bottomReserved` со слайдерами, кнопки «По размеру панелей» (64/72 px) и «Сбросить». Строка «Показывать при наведении к краю» только сообщает состояние: показ скрытого острова при наведении входит в автоскрытие и отдельной настройки не имеет.

«Мониторы»: плитки выбора и карточки строятся из реального списка `Quickshell.screens` (имя, разрешение, модель). Основным считается первый экран, как для акцента и Dynamic Island. Плитки показывают обои выхода, если `Settings` получил `wallpaperManager`. Единственная настройка по мониторам — `hideSecondaryIsland`: переключатель «Верхний остров» второго и следующих мониторов. Остальные строки показывают состояние автоскрытия острова («Всегда» или «Автоскрытие») без переключателя, потому что док, рабочие столы и системный остров показываются на каждом экране. На узкой странице (меньше 640 px) карточки складываются в колонку и показывают только выбранный монитор. Режимы вывода niri страница не меняет.

Страница — `FocusScope` без собственного размера: она занимает область, выданную `Settings`, а прокручивается только вложенный `Flickable` с именем `settings-panels-scroll`. Не вкладывайте в неё не-Item объекты (например, `QtObject`) под `ScrollView`: он перестаёт принимать вложенный `Flickable`, и тот получает высоту 0. Регрессия проверяется в `SettingsSmoke`, а `tests/settings.py` отклоняет вывод со словами `Binding loop`.

## Материалы интерфейса

В разделе «Внешний вид» настройка «Прозрачность» переключает Solid и Frosted Glass для всей оболочки. Плотность поверхностей и нативное размытие описаны в [MATERIALS.md](MATERIALS.md), результаты полировки интерфейса — в [SETTINGS_REVIEW.md](SETTINGS_REVIEW.md).

Там же выбирается акцент. `accentMode` принимает `default`, `automatic` и `manual`; по умолчанию `default`. В этом режиме акцент остаётся авторской лавандой `#C0AFD1`, `accentSoft` — `#80758C`, обои не читаются. `manual` использует `manualAccent`: подходят `#RGB`, `#RRGGBB` и `#AARRGGBB`. Строка сохраняется как `#RRGGBB` в верхнем регистре, альфа-канал отбрасывается. Иное значение становится `#C0AFD1`. Выбор образца или ввод цвета сразу записывает цвет и включает `manual`. `automatic` берёт цвет с обоев первого экрана, `Quickshell.screens[0]`. Если экранов нет, это общий или встроенный фон. Смена фокуса монитора цвет не меняет. Оболочка остаётся на лаванде Nayori, пока разбор не закончен, а также когда у обоев нет выразительного цвета или файл не читается. В автоматическом режиме непустая ошибка разбора показывается как есть. Если ошибки нет, а выразительного цвета нет, статус такой: «На обоях нет выразительного цвета, акцент Nayori остаётся». В остальных режимах статус пустой. Образцы с обоев видны и при своём цвете. `accentPreview`, `accentStatus` и `accentCandidates` в файл не пишутся. Смена режима и цвета применяется сразу, без перезапуска. Сброс возвращает `default` и `#C0AFD1`.

## Фоновая погода

Единственный `services/weather/WeatherService.qml` принадлежит оболочке. После загрузки настроек он получает погоду для заданного города, повторяет запросы по таймеру и немедленно загружает новый город после применения. Изменение интервала перезапускает отсчёт. Пустой город отключает запросы. Открытие и закрытие острова не запускают запросы и не останавливают сервис; все мониторы используют общий результат.

Запросы не пересекаются. При смене города ответ старого запроса отбрасывается. Ошибка сети или некорректный ответ не стирают последний успешный результат в сервисе; интерфейс сообщает об ошибке, следующая попытка выполняется по таймеру или кнопке обновления. Погода хранится в памяти процесса, а интервал — в существующем settings.json как дополнительное поле схемы версии 1.

## Открытие из терминала

Из корня проекта:

```sh
./scripts/nayori-settings
./scripts/nayori-settings --page weather
```

Команда активирует существующее окно. Если Nayori не запущена, команда запускает единственный экземпляр той же оболочки в фоне, ожидает IPC до 10 секунд и открывает настройки. При холодном запуске появляются также панели Nayori. Автозапуск системы не меняется. Параллельные запросы сериализуются через `flock`. Ошибки и неверные идентификаторы разделов возвращают ненулевой код завершения.

Прямой IPC для работающей оболочки:

```sh
qs ipc -p /home/katamy/Projects/nayori call settings open
qs ipc -p /home/katamy/Projects/nayori call settings openPage weather
qs ipc -p /home/katamy/Projects/nayori call settings close
```

Страница Naomi хранит три переключателя: `companionEnabled` (по умолчанию выкл.), `companionDesktopOnly` (выкл.) и `companionReactToPointer` (по умолчанию вкл.; включает небольшой овал над головой, принимающий курсор и клики, см. `docs/NAOMI.md`). Недопустимое значение сбрасывается к умолчанию.

Разделы: `home`, `panels`, `appearance`, `wallpapers`, `weather`. `open` сохраняет текущий раздел; `openPage` выбирает указанный. Существующие `canvas openSettings` и `canvas closeSettings` сохранены как совместимые входы.

`WallpaperManager` независимо хранит обои в `canvas.json`. Имя и аватар берутся из системы. Навигация и состояние открытых окон не сохраняются.

## Проверки

```sh
python3 tests/settings.py
python3 tests/weather-service.py
python3 tests/settings-window.py
bash scripts/check-island.sh
bash scripts/check-canvas.sh
```

Проверки настроек используют временные каталоги и отдельный процесс Quickshell с offscreen-платформой. Пользовательская конфигурация не изменяется.

IPC-тесту нужны локальные Unix-сокеты; в ограниченной песочнице он может потребовать запуск с соответствующим доступом. Проверка контроллера использует отдельную конфигурацию без панелей и временное хранилище. UI-проверка включает все пять страниц при 720×560, 1100×760 и 1600×1000, клавиатурную навигацию, Tab/Shift+Tab, Escape, применение города и прокрутку к полю с фокусом.

Явная проверка в реальной Wayland-сессии:

```sh
python3 tests/settings-window.py --wayland
```

Она открывает только отдельное тестовое окно с app_id `nayori-settings-test`, затем закрывает его через Niri по точному ID, повторно открывает, проверяет PID и фокус, переносит между подключёнными мониторами, изменяет ширину, максимизирует и восстанавливает. После проверки тестовый процесс завершается. Правила композитора не меняются; обычная оболочка не перезапускается.

Вручную остаётся проверить открытие из кнопок живого Dynamic Island, сочетание окна с Bottom Bar и лаунчером, пользовательский переключатель окон, перемещение и изменение размеров мышью, диалог выбора обоев и Escape внутри него. Полный перезапуск ежедневного экземпляра Nayori и отключение монитора проверяются отдельно пользователем.

Исходная рабочая версия перед переносом сохранена в Git-коммите `beace80`. Для отката интерфейса можно вернуть изменённые файлы к этому коммиту; настройки пользователя и схемы обоих хранилищ миграции не требуют.

`python3 tests/root-config.py` компилирует настоящий `shell.qml` на Wayland backend, не создавая его панели, и проверяет привязку анимаций. Проверка требует доступа к Wayland-сокету. Это регрессия для ошибки `Cannot assign to non-existent property "off"`: оболочка теперь задаёт типизированное `Tokens.animationsEnabled`, а `motion.off` вычисляется внутри токенов.


### Логотип и кнопка «Пуск»

Двухуровневая навигация показывает категории слева и разделы выбранной категории рядом.
Поиск охватывает все разделы. Логотип лисы в сайдбаре постоянный.
В разделе «Облик → Пуск» можно выбрать текущую иконку или логотип Nayori.
Ключ `startIconStyle` принимает `"current"` (по умолчанию) и `"fox"`;
неизвестное значение заменяется на `"current"`. Схема остаётся версии 1.
Выбор сразу применяется ко всем кнопкам Пуска и сохраняется общим таймером Settings Service.


«Обзор» открывается непосредственно из основной панели, без второго уровня.
Подпись внизу сайдбара убрана. Иконки категорий используют единую сетку 24 px
и заполненные скруглённые формы.
Переход раздела занимает 220 мс: затухание текущего содержимого, смена данных,
появление нового. Второй уровень плавно раскрывается и меняет содержимое
по тому же принципу. Быстрые действия продолжают переход с текущей прозрачности
и завершаются на последнем выборе. При отключении анимаций переходы завершаются
и дальнейшая навигация выполняется сразу.


### Обзор и общий поиск

Стартовая страница в навигации, заголовке и поиске называется «Обзор».
Она содержит системное имя и аватар, быстрые переходы к обоям, внешнему виду,
панелям и Dynamic Island, а также реальные статусы сети, вывода звука и питания.
Статусы открывают соответствующие разделы. При отсутствии службы показывается
недоступность данных; отсутствие батареи не подменяется нулевым зарядом.
Изображение в большом блоке — превью текущих обоев первого экрана.
Новые фоновые изображения не добавлены. На узком окне блоки располагаются
друг под другом; клавиатурный фокус прокручивает нужную карточку в видимую область.

«Часто открываемые» показывает до четырёх посещаемых разделов: сначала по числу
посещений, при равенстве — по последнему посещению. «Обзор» и повторный выбор уже
открытой страницы не учитываются. Пока истории нет, показывается подсказка.
Settings передаёт наружу сигнал `sectionVisited(key)`, а получает `frequentKeys`.
История принадлежит контроллеру оболочки и не зависит от существования окна.
Отдельный SettingsUsage сохраняет её в
`$XDG_STATE_HOME/nayori/settings-usage.json` (обычно
`~/.local/state/nayori/settings-usage.json`), атомарно, с debounce 250 мс.
Удаление этого файла при остановленной оболочке сбрасывает историю.
Повреждённая или неподдерживаемая схема не перезаписывается; посещения тогда
учитываются только в текущем сеансе. `settings.json` и `canvas.json` не меняют схемы.

Поиск находится между логотипом и «Обзором». Кнопка или Ctrl+F раскрывает общую
строку со всеми разделами, включая «Погоду». В категориях отдельных строк нет.
Escape сначала очищает запрос, затем закрывает поиск и возвращает фокус кнопке.


Без запроса поиск показывает семь последних посещённых
разделов (по давности, а не по частоте); при отсутствии истории выводится подсказка.
Для введённого запроса выбираются до десяти совпадений, недавно посещённые идут первыми.
Под каждым названием указан путь, например «Система / Экран» или
«Облик / Экран блокировки». Обычная навигация по категориям остаётся однострочной.


### Папка обоев

В разделе «Обои» выберите папку: PNG, JPEG и WebP из неё показаны миниатюрами.
Подпапки не просматриваются. Выбор изображения меняет черновик и превью;
фон меняется только кнопкой «Применить». Выбор отдельного файла сохранён.
Папка запоминается отдельно в `wallpaper-library.ini` рядом с `canvas.json`;
формат и ответственность WallpaperManager не изменены.
