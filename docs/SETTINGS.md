# Настройки Nayori

`services/settings/SettingsService.qml` создаётся в `shell.qml` и не зависит от окна. Он читает файл при запуске, сразу применяет правку и пишет её через 250 мс после последнего изменения. Один таймер обслуживает все ключи сервиса. Город погоды и идентификаторы приложений «Пуск» уходят в сервис по своей кнопке. Остальные контролы этих ключей вызывают `update` сразу.

Файл: `$XDG_CONFIG_HOME/nayori/settings.json`, иначе `~/.config/nayori/settings.json`. У `FileView` стоит `watchChanges: false`. Правка файла снаружи читается при следующем запуске. Значения по умолчанию из `defaults()`:

```json
{
  "version": 1,
  "panelModes": {},
  "panelReservations": {},
  "autoHideTop": false,
  "autoHideApps": false,
  "autoHideWorkspaces": false,
  "autoHideStatus": false,
  "hideSecondaryIsland": false,
  "fullscreenIslandOutput": "",
  "topReserved": 0,
  "bottomReserved": 0,
  "animationsEnabled": true,
  "companionEnabled": false,
  "companionStyle": "current",
  "companionDesktopOnly": false,
  "companionReactToPointer": true,
  "companionSystemLines": true,
  "fullscreenCompanionOutput": "",
  "companionScreen": "primary",
  "companionSide": "right",
  "colorScheme": "dark",
  "surfaceStyle": "solid",
  "accentMode": "default",
  "manualAccent": "#C0AFD1",
  "startIconStyle": "current",
  "weatherCity": "",
  "weatherRefreshMinutes": 15,
  "islandRotationEnabled": true,
  "islandRotationSeconds": 15,
  "preferredTerminal": "kitty",
  "preferredFileManager": "io.github.lgse.Strata",
  "niriColorIntegration": true,
  "strataThemeIntegration": true,
  "mixerSources": [],
  "notificationsEnabled": true,
  "notificationReception": null,
  "notificationSources": [],
  "notificationsDndUntil": 0,
  "notificationsDndManual": false
}
```

`topReserved` и `bottomReserved` ограничиваются 0–200 и округляются до шага 4. `weatherRefreshMinutes` — целое от 1 до 180. `islandRotationSeconds` округляется и зажимается в 5–120. `weatherCity` обрезает пробелы по краям. `fullscreenIslandOutput` и `fullscreenCompanionOutput` обрезаются и не длиннее 256 символов. `colorScheme` — `dark` или `light` (по умолчанию `dark`). `surfaceStyle` — `solid` или `frosted`. `accentMode` — `default`, `automatic` или `manual`. `startIconStyle` — `current` или `fox`. `companionStyle` — `current`, `pixel-art`, `layered` или `haori`. `companionScreen` — `primary` или `secondary`. `companionSide` — `left` или `right`. Пустые `preferredTerminal` и `preferredFileManager` возвращаются к значениям по умолчанию.

`manualAccent` принимает `#RGB`, `#RRGGBB` и `#AARRGGBB`. В файл пишется `#RRGGBB` в верхнем регистре, альфа отбрасывается. Иная строка становится `#C0AFD1`.

`notificationsEnabled` — логический, по умолчанию включён. `notificationReception` — `true`, `false` или `null`. `null` и любое иное значение значат, что выбора ещё нет. `notificationsDndManual` — только `true` включает режим до ручного выключения; иное значение выключает его. `notificationsDndUntil` — целое число миллисекунд, абсолютное время окончания. Ноль, отрицательное и нечисловое значение значат, что таймера нет. `notificationSources` — массив до 200 записей `{key, title, desktopEntry, appName, mode}`. `key` начинается с `entry:` или `name:`. `mode` — `normal`, `expanded` или `off`; иное значение становится `normal`. Повторы ключа отбрасываются.

Неизвестный ключ в `defaults()` не появляется из файла сам по себе: известное поле неверного типа получает значение по умолчанию. Поля, которых нет в `defaults()`, остаются в документе и записываются снова. Форматирование JSON при записи может измениться.

До `ready` запись запрещена. Отсутствующий файл создаётся при первом изменении. Запись атомарная. Ошибка оставляет значения в сеансе. Нижняя строка окна предлагает «Повторить запись». Полный текст виден при наведении, если он не помещается.

Неподдерживаемая `version` ставит состояние `unsupported`. Изменения живут только в сеансе и на диск не пишутся. Повреждённый JSON получает состояние `corrupt` и сам не заменяется. «Восстановить настройки» запускает `scripts/settings-backup.py`: копия `settings.json.backup-*` в том же каталоге, доступ только владельцу. Замена исходного файла начинается после успешной копии. Затем сервис пишет текущие рабочие значения. Ошибка копии замену блокирует. Нужен Python 3.

Ошибка чтения, кроме отсутствующего файла, ставит `unreadable`: «Не удалось прочитать settings.json. Проверьте доступ к файлу и перезапустите Nayori.»

`flush(true)` ждёт текущую запись и пишет ожидающие изменения. Он вызывается из `Component.onDestruction`. Закрытие окна сервис не уничтожает и `flush` не вызывает. SIGKILL и выход без уничтожения QML не гарантируют сохранение последних 250 мс.

`accentPreview`, `accentStatus` и `accentCandidates` в файл не пишутся.

## Окно

`surfaces/settings/Settings.qml` — контейнер навигации и страниц. Страницы получают значения свойствами и отдают действия сигналами. `SettingsController` связывает сигналы с `settingsService.update`. Обратная запись из программной смены свойства не запускается.

`surfaces/settings/SettingsWindow.qml` — обычный `FloatingWindow`, не LayerShell и не дочернее окно острова. Niri ставит его в тайлы, выбирает монитор, фокус, размер и максимизацию. Запрошенный размер — 1100×760, минимум — 720×560. Заголовок — `Nayori Settings`. App id всего процесса Quickshell — `nayori` (`pragma AppId` в `shell.qml`).

Боковая колонка складывается из рельса и второго столбца. Рельс — 76 px, при ширине окна меньше 960 — 68. Второй столбец — 232 px, в компактном окне — 184. На «Обзоре» без открытого поиска второго столбца нет, виден только рельс. Иконки категорий — 22×22. Подписи категорий на рельсе: «Обзор», «Система», «Устройства», «Облик», «Naomi», «Окна», «Приложения», «NayoriOS». Группа в данных при этом называется «Персонализация», а на рельсе показана как «Облик».

Кнопка поиска стоит на рельсе под логотипом лисы. Ctrl+F открывает поле. Без запроса показываются до семи недавних разделов, кроме «Обзора». Запрос ищет название, путь и описание и оставляет до десяти совпадений. Недавние идут первыми. Escape сначала очищает запрос, затем закрывает поиск. Без поиска Escape закрывает окно и не завершает Nayori. Меню страницы, у которого свой Escape, обрабатывает его само, пока у него фокус.

Смена раздела длится `tokens.motion.base` (220 мс): прозрачность падает, содержимое меняется в `SettingsPageMotion`, затем появляется. Выключенные анимации завершают переход сразу. Прокрутка страниц — `SettingsScroll`: вертикальная полоса с `active: true`. Фокус вызывает `reveal` и докручивает элемент в видимую область.

Контроллер создаёт одно окно, затем показывает и скрывает его. Обычное закрытие сбрасывает флаг и сохранённый id окна niri. Если объект уничтожен, следующий запрос создаёт новое. Активация ищет PID процесса, app id и заголовок, затем вызывает `Niri.focusWindow` по точному id и снова проверяет PID. Закрытые id в выбор не возвращаются. Без niri остаётся `requestActivate`. До сорока попыток с шагом 100 мс.

Окно помнит раздел, пока жив процесс. После полного перезапуска оболочки оно закрыто. Открытие лаунчера или острова его не закрывает. Открытие настроек закрывает лаунчер и журнал буфера.

История посещений принадлежит `services/settings/SettingsUsage.qml`, не окну. Файл: `$XDG_STATE_HOME/nayori/settings-usage.json`, обычно `~/.local/state/nayori/settings-usage.json`. Запись атомарная, пауза 250 мс, `watchChanges: false`. Удаление файла при остановленной оболочке сбрасывает историю. Повреждённая или чужая версия не перезаписывается, визиты тогда живут только в сеансе. «Обзор» и повтор уже открытой страницы не считаются. «Часто открываемые» на обзоре показывает до четырёх ключей: сначала по числу визитов, при равенстве — по последнему. В известные ключи истории не входит `integrations`. `settings.json` и `canvas.json` эта история не меняет.

Нижняя строка «Изменения сохраняются автоматически.» стоит на `home`, `panels`, `appearance`, `weather`, `start`, `island`, `integrations`, `notifications` и на разделах, чей ключ начинается с `naomi`.

### Уведомления

Раздел `notifications` пишет показ, системный приём, режим «Не беспокоить» и список приложений. История уведомлений в файл не входит: она по-прежнему живёт в памяти и пропадает при перезапуске.

«Показывать уведомления» — `notificationsEnabled`. Выключенный переключатель не сохраняет новые уведомления и не показывает их ни в свёрнутом, ни в развёрнутом острове. Уже сохранённые записи остаются. Это относится и к внутренним уведомлениям Nayori, например к захвату экрана.

«Принимать системные уведомления» запускает и останавливает `services/island/Notifications.qml`. Пока `notificationReception` равен `null`, приём включается только при `NAYORI_NOTIFICATIONS=1`. После выбора в настройках решает сохранённое значение, переменная его не перебивает. Страница показывает «Приём выключен», «Запуск приёма…» или «Приём работает». Если имя `org.freedesktop.Notifications` занято или D-Bus недоступен, остаётся текст ошибки сервиса и подсказка включить приём снова. Nayori чужое имя не отбирает.

«Не беспокоить» включается на 15 минут, 1 час, 2 часа, на число минут от 1 до 1440 или до ручного выключения. Срок хранится в `notificationsDndUntil` как абсолютное время. Ручной режим — `notificationsDndManual: true` и нулевой срок. На странице видно «до ЧЧ:ММ» или «Пока не выключите». «Выключить» сбрасывает оба поля. Если срок прошёл, пока Nayori не работала, при следующем запуске режим уже выключен.

Во время режима уведомление сохраняется в истории развёрнутого острова и не попадает в свёрнутый. После окончания оно там тоже не появляется. Просмотр и прочтение остаются отдельными признаками.

Приложение попадает в `notificationSources` при первом уведомлении. Источник определяется по `desktopEntry`, а если его нет — по имени приложения. Для каждого источника три режима: «Обычный показ», «Только в развёрнутом острове», «Отключено». Отключённые новые уведомления в историю не пишутся. Смена режима сразу меняет свёрнутый остров; уже сохранённую историю она не удаляет.

### Звук

`mixerSources` хранит источники микшера панели. По умолчанию список пустой. Запись добавляется, когда оболочка впервые видит поток воспроизведения. Ключ — `node.name`. `title` — последнее имя из desktop-файла или имя потока. `hidden: true` убирает источник из микшера, запись остаётся. На странице «Звук» список закрыт: строка «Источники микшера» показывает число источников и сколько из них скрыто. В открытом списке галочка оставляет источник в микшере.

### Панель задач

Страница `panels` — две карточки. «Общие параметры»: переключатель «Мониторы» строит плитки из `Quickshell.screens`: имя, разрешение, модель. Для верхнего острова, дока приложений, рабочих столов и трея на каждом экране доступны «Показывать всегда», «Авто-скрытие», «Не отображать». Селект расположен справа от названия. Отдельного общего блока автоскрытия нет. Отступы «Сверху» и «Снизу» в карточке монитора меняют `panelReservations[имя_выхода].top` и `.bottom`; «По размеру панелей» ставит 64 и 72, «Сбросить» — 0 и 0.

`panelReservations` хранит отступы отдельно для каждого подключения: `{"DP-1":{"top":64,"bottom":72},"DP-2":{"top":0,"bottom":24}}`. Диапазон 0–200 px, шаг 4 px. Без явного значения применяются прежние общие `topReserved` и `bottomReserved`. Это резерв места для окон, как и до обновления.

`panelModes` хранит режимы по имени подключения: например, `{"DP-1":{"top":"hidden","apps":"auto"},"DP-2":{"status":"always"}}`. Ключи частей: `top`, `apps`, `workspaces`, `status`; режимы: `always`, `auto`, `hidden`. Некорректные значения отбрасываются. Отключение монитора не удаляет настройки. Для частей без явного режима продолжают действовать старые `autoHide*`, `hideSecondaryIsland` и перенос острова при полном экране, чтобы обновление сохраняло прежнее поведение. Явный режим верхнего острова заменяет старое правило вывода для этого экрана.

При автоскрытии элементы плавно выдвигаются от края и меняют прозрачность: верхний остров — появление 360 мс и исчезновение 420 мс, нижние панели — 520 и 580 мс; кривая `InOutCubic`. Блюр следует реальным координатам содержимого в неподвижной поверхности. Наведение на край раскрывает элемент, открытое меню удерживает его, уход указателя запускает задержку 650 мс. Глобальное отключение анимаций делает переход мгновенным. «Не отображать» отключает также краевой триггер. В режиме «Показывать всегда» сохраняются общие правила полного экрана и отсутствие пустого дока приложений.

При ширине страницы от 652 px карточки мониторов встают в две колонки. Ниже этого порога видна только карточка выбранного монитора. Режимы вывода niri страница не меняет.

Страница — `FocusScope` без собственного размера. Прокручивается вложенный `Flickable` с именем `settings-panels-scroll`. Не вкладывайте не-Item, например `QtObject`, под `ScrollView`: тот перестаёт принимать вложенный `Flickable`, и высота становится 0. `tests/settings.py` отклоняет вывод со словами `Binding loop`.

### Экран

Страница `display` записывает блоки `output` в файл, который открывает niri: `NIRI_CONFIG`, иначе `$XDG_CONFIG_HOME/niri/config.kdl` или `~/.config/niri/config.kdl`. `noctalia.kdl`, `nayori-accent.kdl` и `nayori-overview.kdl` не меняются. Если единственный блок монитора лежит в одном из этих файлов, страница показывает причину и не создаёт второй блок с тем же именем.

Перед заменой рядом с файлом пишется копия `.имя.nayori-backup-…`. Затем `niri validate -c` проверяет основной файл. Ошибка проверки или записи возвращает прежний текст. Без команды `niri` страница не записывает файл.

Схема «Расположение мониторов» перетаскивает выходы. Координаты X и Y считаются по схеме и на карточках только показываются. Отпущенный монитор всегда встаёт к краю соседнего, отдельного переключателя для этого нет. «Обновить» заново читает подключённые мониторы. Клик по монитору на схеме показывает только его карточку. На карточке неосновного монитора первым пунктом стоит выключенный переключатель «Основной монитор». На основном его нет. «Применить» переносит строку `focus-at-startup` на выбранный выход и снимает её с остальных блоков, которые Nayori может менять. Метка «Основной» и звезда в правом верхнем углу плитки на схеме показывают эту строку, а если строки нет — первый экран Quickshell. Разрешение и частота выбираются отдельно и записываются одной строкой `mode`, например `2560x1440@164.836`. Масштаб от 0,1 до 10, это положение, поворот (`normal`, `90`, `180`, `270`, `flipped`, `flipped-90`, `flipped-180`, `flipped-270`), строка `off` и переменная частота (`variable-refresh-rate`, в том числе `on-demand=true`) применяются кнопкой «Применить». Это опасные правки: 15 секунд страница ждёт «Оставить». «Вернуть» и конец срока восстанавливают копию. После успешной записи и после отката страница отдельно просит niri перечитать файл командой `niri msg action load-config-file`. Проверки эту команду не вызывают.

Список режимов читается через `niri msg outputs`. Если сокета нет, разрешение и частота вписываются отдельно, например `1920x1080` и `60`, и складываются в ту же строку `mode`. Пустые режим и положение убирают свои строки. Чужой блок `output` не переписывается. Отключение монитора блок не удаляет.

### Мышь

Страница `mouse` пишет `input.mouse` и `input.touchpad` в том же файле. Поддержанные ключи niri 26.04, проверенные `niri validate` у установленной сборки: для мыши `off`, `natural-scroll`, `left-handed`, `middle-emulation`, `accel-speed` от −1 до 1, `accel-profile` (`flat`, `adaptive`), `scroll-method` (`no-scroll`, `two-finger`, `edge`, `on-button-down`), `scroll-factor` от 0 до 100. Для тачпада те же, плюс `tap`, `dwt`, `dwtp`, `drag` со значением `true` или `false`, `drag-lock`, `click-method`, `tap-button-map`, `disabled-on-external-mouse`, `scroll-button` и `scroll-button-lock`.

Флаги включаются строкой без значения и выключаются удалением строки. `tap false` niri не принимает. Неизвестный ключ отклоняется, файл не меняется. Запись идёт с той же копией и `niri validate`. Таймер картинки для мыши и тачпада не используется. Если в этот момент ждёт подтверждения правка экрана в том же файле, запись устройства откладывается.

### Клавиатура

Страница `keyboard` пишет `input.keyboard`: `xkb.layout`, `xkb.variant`, `xkb.options`, `repeat-delay`, `repeat-rate`, `track-layout` (`global` или `window`) и `numlock`. Пустое поле убирает строку. `model` и `rules`, если они уже есть, не меняются. Текущий список раскладок по-прежнему читает `niri msg keyboard-layouts`. Страница этот список не переключает.

Проверка и копия те же, что у мыши. После успешной записи страница просит niri перечитать файл.

### Внешний вид

«Тема» переключает `colorScheme`: «Тёмная» или «Светлая». Смена применяется сразу ко всей оболочке и сохраняется между запусками. Светлая палитра использует молочные поверхности с лавандовым подтоном, тёмный текст и контрастные акценты. Цвета с обоев сохраняют оттенок, а поверхности становятся светлыми. Solid и Frosted Glass работают в обеих темах. Экран блокировки и экспорт темы получают уже рассчитанные токены.

«Прозрачность» выбирает `surfaceStyle`: «Solid» или «Frosted Glass». Плотность и размытие описаны в [MATERIALS.md](MATERIALS.md).

«Акцент» выбирает `accentMode`. «Лаванда Nayori» (`default`) держит `#C0AFD1` и не читает обои. «Свой цвет» (`manual`) использует `manualAccent`. «С обоев» (`automatic`) берёт цвет с обоев первого экрана, `Quickshell.screens[0]`. Смена фокуса niri цвет не меняет. Пока разбор не закончен, цвет невыразительный или файл не читается, оболочка остаётся на лаванде. В автоматическом режиме непустая ошибка разбора показывается как есть. Если ошибки нет, а цвета нет, статус такой: «На обоях нет выразительного цвета, акцент Nayori остаётся». В остальных режимах статус пустой. Образцы с обоев видны и при своём цвете. Выбор образца пишет цвет и включает `manual`. Поле «Цвет» видно только в режиме `manual`. Сброс возвращает `default` и `#C0AFD1`. Смена применяется сразу.

Переключатель анимаций пишет `animationsEnabled`.

### Dynamic Island и погода

Раздел `island` пишет `islandRotationEnabled` и `islandRotationSeconds`. Подпись переключателя: «Смена страниц острова». Тот же раздел встраивает `WeatherPage`.

Город меняется кнопкой «Применить». Интервал «Интервал обновления, мин» уходит в сервис при правке числа. Пустой город отключает запросы. Один `services/weather/WeatherService.qml` принадлежит оболочке: после загрузки настроек он запрашивает город, повторяет по таймеру и сразу грузит новый город после применения. Смена интервала перезапускает отсчёт. Запросы не пересекаются. Ответ старого города отбрасывается. Ошибка сети или ответ не стирают последний успешный результат. Погода живёт в памяти процесса. Интервал лежит в `settings.json` как поле версии 1.

Раздел `weather` в боковой колонке скрыт (`sidebar: false`). Его открывают поиск, `openPage weather` и кнопка «Выбрать город» на острове.

### Пуск

«Текущая иконка» и «Логотип Nayori» пишут `startIconStyle` сразу. Логотип в настройках от этого не меняется. «Сохранить терминал» и «Сохранить файловый менеджер» пишут `preferredTerminal` и `preferredFileManager`. Пустое поле при записи возвращает `kitty` и `io.github.lgse.Strata`.

### Интеграции

«Цвета niri» — `niriColorIntegration`, по умолчанию включено. Описание в интерфейсе: пять цветов акцента в `nayori-accent.kdl`, файл `noctalia.kdl` не изменяется. «Тема Strata» — `strataThemeIntegration`, по умолчанию включено. Ошибка и уведомление Strata показываются на странице и в файл настроек не пишутся.

### Naomi

Три раздела: `naomi`, `naomi-look`, `naomi-place`. Поведение окна — в [NAOMI.md](NAOMI.md). Ключи здесь такие.

`companionEnabled` по умолчанию выключен. Подпись: «Показывать Naomi на рабочем столе». `companionStyle`: «Текущий» (`current`), «Pixel art» (`pixel-art`), «Naomi v3» (`layered`), «Хаори» (`haori`). `companionDesktopOnly` по умолчанию выключен, подпись «Только на рабочем столе». `companionReactToPointer` по умолчанию включён, подпись «Реагировать на курсор». `companionSystemLines` по умолчанию включён, подпись «Комментировать системные события». Приветствие и поглаживание от этого переключателя не зависят.

`companionScreen` — `primary` или `secondary`. Иное значение становится `primary`. `companionSide` — `right` или `left`, нижний угол. Иное значение становится `right`. Пока выбран второй монитор, «Монитор при полном экране» скрыт. Если экранов больше одного и выбран основной, выбор пишет `fullscreenCompanionOutput`. Пустая строка — пункт «Не показывать». Нестроковое или слишком длинное значение этого поля становится пустой строкой.

### Обои

Страница описана в [CANVAS.md](CANVAS.md). Выбор миниатюры меняет черновик. Фон меняется кнопкой «Применить».

## Открытие из терминала

Из корня проекта:

```sh
./scripts/nayori-settings
./scripts/nayori-settings --page weather
```

Команда активирует существующее окно. Если Nayori не запущена, скрипт запускает один экземпляр `qs -p <каталог> --no-duplicate --daemonize`, ждёт IPC до 10 секунд и открывает настройки. При холодном запуске появляются и панели. Автозапуск системы не меняется. Параллельные запросы сериализуются через `flock -w 12`. Ошибки и неизвестный ключ дают ненулевой код.

Скрипт принимает ключи из своего `case`: `home`, `panels`, `appearance`, `wallpapers`, `weather`, `display`, `sound`, `notifications`, `power`, `network`, `localsend`, `bluetooth`, `mouse`, `keyboard`, `shortcuts`, `start`, `island`, `lockscreen`, `windows`, `alttab`, `workspaces`, `defaults`, `autostart`, `updates`, `about`. Ключей `naomi`, `naomi-look`, `naomi-place` и `integrations` в этом списке нет. Их открывает прямой IPC.

```sh
qs ipc -p /home/katamy/Projects/nayori call settings open
qs ipc -p /home/katamy/Projects/nayori call settings openPage weather
qs ipc -p /home/katamy/Projects/nayori call settings openPage naomi
qs ipc -p /home/katamy/Projects/nayori call settings close
```

## Проверки

```sh
python3 tests/settings.py
python3 tests/niri-config-apply.py
node tests/monitor-layout.cjs
python3 tests/weather-service.py
python3 tests/settings-window.py
bash scripts/check-island.sh
bash scripts/check-canvas.sh
```

Проверки настроек используют временные каталоги и отдельный процесс Quickshell с offscreen-платформой. Пользовательская конфигурация не изменяется.

IPC-тесту нужны локальные Unix-сокеты. В ограниченной песочнице он может потребовать запуск с соответствующим доступом. Проверка контроллера использует отдельную конфигурацию без панелей и временное хранилище. `tests/smoke/SettingsSmoke.qml` обходит все разделы из `sections` на размерах 720×560, 1100×760, 1600×1000 и 880×680.

Явная проверка в реальной Wayland-сессии:

```sh
python3 tests/settings-window.py --wayland
```

Она открывает отдельное окно с app id `nayori-settings-test`, закрывает его через niri по точному id, снова открывает, проверяет PID и фокус, переносит между подключёнными мониторами, меняет ширину, максимизирует и восстанавливает. Затем тестовый процесс завершается. Правила композитора не меняются. Обычная оболочка не перезапускается.

`python3 tests/root-config.py` компилирует `shell.qml` на Wayland и проверяет привязку анимаций. Нужен сокет Wayland. Это регрессия ошибки `Cannot assign to non-existent property "off"`: оболочка задаёт `Tokens.animationsEnabled`, а `motion.off` считается внутри токенов.

Исходная рабочая версия перед переносом окна сохранена в коммите `beace80`. Этот коммит в репозитории есть. Возврат интерфейса к нему — отдельное решение. Схемы `settings.json` и `canvas.json` миграции из этого документа не требуют.


## Bluetooth в трее

На странице «Устройства → Bluetooth» переключатель «Показывать Bluetooth в системном трее» управляет общим параметром `bluetoothIconVisible` (по умолчанию `true`). ПКМ по значку → «Скрыть иконку» записывает тот же параметр. Скрытие не выключает адаптер. Меню и настройки используют один сервис оболочки. Подробности и зависимости — [Bluetooth](BLUETOOTH.md).

## WireGuard в меню сети

В трее и на странице «Система → Сеть» доступен общий блок WireGuard: импорт `.conf`, список профилей NetworkManager, подключение и отключение. Состояние обновляется по событиям; закрытие меню не прерывает начатую операцию. Профили и ключи хранит NetworkManager. Подробности и проверки — [WireGuard](WIREGUARD.md).
